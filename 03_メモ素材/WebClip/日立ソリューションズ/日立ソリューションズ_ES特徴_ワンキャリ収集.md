## ES全体の特徴

### 1. 「ITのおもしろさ」はほぼ必須論点

直近の本選考ESでは、「ITのおもしろさ」と「IT業界に向けた現在の取り組み」をセットで聞く設問が目立つ。

回答では、ITを単なる便利なツールではなく、現場の課題を仕組みから変えるものとして捉えているものが多い。

- 属人化を可視化・標準化できる
- 業務プロセスそのものを変革できる
- 人の判断や対応を支援できる
- 組織全体の生産性や品質を底上げできる
- 生活上の制約や不便を解消できる
- データ活用で意思決定の質を高められる

### 2. 「現在取り組んでいること」は資格・学習・ニュースで具体化する

IT未経験でも、学習行動を具体的に書く回答が多い。単に「勉強している」ではなく、何を通じて何を理解しようとしているかまで書くと強い。

- ITパスポート
- 基本情報技術者試験
- Progate
- Java、JavaScript、Pythonなどの基礎学習
- 生成AIやDX事例の調査
- IT関連ニュース、企業導入事例の分析
- セキュリティやITプラットフォームへの関心

### 3. 志望理由は「日立グループ」だけでは弱く、独自性まで書く

日立グループの技術基盤や総合力に触れる回答は多いが、それだけで終わらせず、日立ソリューションズ固有の強みへ落とす必要がある。

よく使われる独自性は次の通り。

- 自社ソリューションと他社製品を組み合わせる柔軟性
- マルチベンダー、アライアンス製品の活用
- 顧客ごとに最適解を設計できること
- 上流工程から運用まで一貫して関われること
- 顧客の業務に深く入り込み、課題解決に伴走すること
- サステナビリティやSXへの姿勢
- セキュリティ、ITプラットフォーム、ワークスタイル変革などの領域

### 4. SE志望は「現場課題を技術で仕組みにする」が中心

SEの回答では、顧客の業務理解、要件整理、実装、導入後の改善までを意識した内容が多い。

- 現場の声を聞く
- 表面的な要望ではなく潜在課題を見つける
- 業務プロセスを整理する
- 誰でも使える仕組みに落とし込む
- 導入後も改善を続ける
- 技術と人をつなぐ

### 5. 営業志望は「顧客理解」と「SEへの橋渡し」が重要

営業職のESでは、単なる販売ではなく、顧客の業務背景や意思決定の意図を理解し、SEや開発側へ正確に伝える役割として書かれている。

- 顧客の潜在ニーズを引き出す
- 業務背景や感情まで踏まえて提案する
- SIや自社ソリューションを組み合わせる
- 顧客と開発の架け橋になる
- 長期的な信頼関係を築く

### 6. 原体験は「身近な非効率」「支援経験」「改善経験」が使われやすい

回答の起点として、アルバイト、塾講師、家庭教師、サークル、ゼミ、研究、家族の経験などが使われている。

特に強いのは、課題を見つけて仕組み化・改善した経験。

- Excelや共有ツールで業務を可視化した
- 手作業や属人化を標準化した
- シフト作成やマニュアル作成を改善した
- 生徒・顧客・利用者ごとに最適な支援をした
- 予約システムやITツールで生活の不便が解消された経験
- 部活動やゼミで意見調整し、周囲を巻き込んだ経験

## 回答の基本型

### ITのおもしろさ

```text
私が感じるITのおもしろさは、[現場課題・属人化・制約]を[可視化・標準化・自動化・仕組み化]し、[組織や人の行動変容]まで実現できる点にある。

そう考えた背景は、[自分の経験]で[具体的な非効率や課題]を見たことにある。

現在は、[資格・プログラミング・ニュース・事例分析]を通じて、ITの基礎知識と社会実装の理解を深めている。
```

### 志望理由

```text
日立ソリューションズを志望する理由は、[日立グループの技術基盤]に加え、[自社・他社ソリューションを柔軟に組み合わせる力]を通じて、顧客ごとの最適解を提供できる点に魅力を感じたからである。

特に、[上流工程から運用までの一貫性 / 顧客業務への深い理解 / マルチベンダー / セキュリティ / ITプラットフォーム / SX]に惹かれている。

自分の[経験・強み]を活かし、[顧客課題の解決 / 業務効率化 / 社会課題の解決 / 安定した基盤づくり]に貢献したい。
```

### 何を活かして何を実現したいか

```text
私は、[過去経験]で培った[課題整理力・対話力・巻き込み力・粘り強さ・分析力]を活かし、[SE/営業]として[顧客の本質課題を捉えたソリューション提供]を実現したい。

過去には、[具体的な課題]に対して[自分の行動]を行い、[改善結果]につなげた。

この経験を活かし、日立ソリューションズでは[顧客理解・最適な技術選定・導入後の改善・顧客と開発の橋渡し]を通じて、[実現したい価値]を生み出したい。
```

## 自分のESで使えそうな方向性

- AIやデータ活用を、単なる興味ではなく「現場課題を仕組み化する力」として語る。
- 研究・開発・AI活用経験がある場合は、技術を使った課題解決や再現性ある仕組み作りに接続する。
- 志望理由では、日立グループの技術基盤だけでなく、日立ソリューションズの「顧客ごとの最適解」「マルチベンダー」「上流から運用まで」「現場伴走」に触れる。
- SE志望なら、要件定義・実装・運用改善まで意識する。
- 営業志望なら、顧客の潜在課題を引き出し、SEへ正確につなぐ役割を意識する。
