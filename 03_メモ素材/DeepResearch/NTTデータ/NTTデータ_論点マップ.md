# NTTデータ 論点マップ

## 目的

Source Noteを横断し、NTTデータが見ている中長期の未来、技術変化、開発方法の変化、そこから浮かび上がる人材像を整理する。

このノートは長期展望レポートの設計図であり、事実は `01_企業別/NTTデータ/企業研究/`、選考で使う見立ては `01_企業別/NTTデータ/` に切り出す。

## 結論仮説

NTTデータは、AIを単独の技術として導入する会社ではなく、AI・データ・クラウド・インフラ・業界知見・品質保証・グローバルデリバリーを組み合わせて、顧客の業務変革と社会基盤の高度化を担う会社へ進もうとしている。

そのため、求められる人材像は「AIを使える人」では足りない。顧客業務を構造化し、AIやデータを商用システムへ安全に組み込み、品質・透明性・説明責任を担保しながら、顧客・社内外専門家・AIエージェントと共創できる人材が重要になる。

- [[../SourceNotes/NTTデータ/011_AIサービス]]

読み方:

NTTデータにとってAIは、単なる社内効率化ツールではなく、顧客の業務変革、業界別ソリューション、グローバル成長、データセンター投資、人材育成を結びつける経営テーマである。

### 2. 業界知見をAIサービスへ転換する

読み方:

## 論点2 技術は何を変えるか

### 1. AIは補助ツールから開発主体の一部へ移る

根拠:

- [[../SourceNotes/NTTデータ/002_AI-Native開発デザイン戦略]]
- [[../SourceNotes/NTTデータ/003_AI-Native開発で広がるSIerの可能性]]
- [[../SourceNotes/NTTデータ/007_GitHub連携]]
- [[../SourceNotes/NTTデータ/008_GitHub Copilot開発支援]]

要点:

- GitHub Copilot活用は、AI-Assisted開発として開発現場へ生成AIを入れる動き。
- AI-Native開発は、AIを開発主体の一部に据え、要件・設計・ルール・証跡をAI-readyにする考え方。
- 人間の役割は、実装中心から、目的設定、文脈設計、品質判断、説明責任へ移る。

読み方:

開発方法の変化は、単にコード生成が速くなることではない。AIが働けるように、要件、設計、タスク、品質基準、証跡を整えることが重要になる。

### 2. 商用システムでは品質・透明性・アカウンタビリティが中心になる

根拠:

- [[../SourceNotes/NTTデータ/002_AI-Native開発デザイン戦略]]
- [[../SourceNotes/NTTデータ/012_Responsible Software Development]]

要点:

- AI-Native開発では、機能性、品質、透明性、アカウンタビリティが商用システム開発の責務として整理されている。
- Responsible Software Developmentでは、生成AI利用時の情報管理、AI利用統制、品質、セキュリティが重要になる。

読み方:

AIが生成したコードや成果物でも、最終的な説明責任は人間と組織に残る。大規模SIerとしての価値は、AIを使って速く作ることだけでなく、顧客が説明できる形で品質を担保することにある。

### 3. AI時代のインフラ・データ・セキュリティが重要になる

根拠:

- [[../SourceNotes/NTTデータ/001_Technology Foresight 2026]]
- [[../SourceNotes/NTTデータ/005_金融共同AI基盤]]
- [[../SourceNotes/NTTデータ/011_AIサービス]]

要点:

- Technology Foresightは、AI時代にインフラ、半導体、エネルギー、主権性、透明性が重要になると示す。
- 金融共同AI基盤は、AIガバナンス、データ統合、マルチベンダー設計を掲げる。
- AIサービスは、AI adoptionを企業全体の業務・データ・成長へ接続する。

読み方:

AI活用の成否はモデルだけでは決まらない。データ基盤、既存システム、クラウド、セキュリティ、ガバナンス、運用を含めた設計が重要になる。

## 論点3 現場の仕事はどう変わるか

### 1. 実装者から設計者・検証者・説明者へ

根拠:

- [[../SourceNotes/NTTデータ/002_AI-Native開発デザイン戦略]]
- [[../SourceNotes/NTTデータ/003_AI-Native開発で広がるSIerの可能性]]
- [[../SourceNotes/NTTデータ/012_Responsible Software Development]]

変化:

- AIが実装やテストの一部を担う。
- 人間は、何を作るべきか、どの品質基準を満たすべきか、なぜその設計でよいのかを定義・検証する。
- 開発者は、コードだけでなく、根拠、証跡、レビュー、説明を扱う。

### 2. PM・品質保証・監査の重要性が高まる

根拠:

- [[../SourceNotes/NTTデータ/002_AI-Native開発デザイン戦略]]

変化:

- スリーラインモデルにより、開発チーム、PMO・品質保証、内部監査、ガバナンス体の役割が整理されている。
- AIが開発に関与するほど、プロセス設計、品質ゲート、監査可能性が重要になる。

### 3. 業務・業界知識と技術を接続する力が重要になる

根拠:

- [[../SourceNotes/NTTデータ/004_OpenAI戦略提携]]
- [[../SourceNotes/NTTデータ/005_金融共同AI基盤]]
- [[../SourceNotes/NTTデータ/011_AIサービス]]

変化:

- 業界特化型AIエージェントは、業界知識なしには設計できない。
- 金融共同AI基盤では、金融業務、規制、データ、ガバナンス、AIを横断する必要がある。
- 現場SEにも、業務理解と技術実装の接続が求められる。

## 論点4 求められる人材像

### 1. 業務を構造化できる人

根拠:

- AI-Native開発では、AIが扱えるように要件・設計・タスクを構造化する必要がある。
- 業界特化型AIエージェントでは、業務知識をAIに落とし込む必要がある。

人材像:

- 顧客の曖昧な課題を分解し、AI・開発チーム・顧客が扱える形にする人。

### 2. 品質・透明性・説明責任を担保できる人

根拠:

- AI-Native開発の4責務。
- Responsible Software DevelopmentのAI利用統制。

人材像:

- AIの出力を鵜呑みにせず、根拠、証跡、テスト、レビューを設計できる人。

### 3. AIと人間の協働を設計できる人

根拠:

- Technology Foresightの人とAIの協調。
- AI-Native開発のAIエージェントを含む開発マネジメント。
- AI時代の人材変革レポート。

人材像:

- 人間、顧客、チーム、AIエージェントの役割分担を設計し、成果へつなげる人。

### 4. 業界知見とAI技術を接続できる人

根拠:

- OpenAI提携の業界特化AIエージェント。
- 金融共同AI基盤。

人材像:

- 金融、公共、製造、流通などの業界課題を理解し、AI・データ・既存システムへ接続する人。

### 5. 技術変化を経営・社会課題へ接続できる人

根拠:

- Technology Foresight。
- ConsultingページのForesight起点の提言。
- AIサービスページ。

人材像:

- 技術トレンドを、顧客の事業変革、業務変革、社会基盤の高度化へ接続できる人。
