# PwC GD対策シート 農業DX

## まず結論

農業DXは、「AIやドローンを入れる話」ではなく、農業の生産・経営・流通をデータでつなぎ、少ない人手でも安定して収益を出せる仕組みに変える話。

GDでの勝ち筋は、次の順番で考えること。

```text
誰の農業かを決める
作業工程を分解する
一番詰まっている工程を選ぶ
その工程に合うデジタル施策を当てる
導入障壁と定着策まで話す
```

いきなり「ドローン」「AI」「IoT」と言わない。  
先に「どの工程の、どの負担を、どのKPIで改善するか」を決める。

## GDで出そうなお題

- ITを用いて農業の問題を解決する。
- 日本の農林水産業を向上させるためのデジタル施策を提案する。
- スマート農業の技術的課題と、その解決策を考える。
- 農業におけるAIや新しい技術を実用化する際の技術的な問題を考える。
- 労働力不足に対応するため、農業にどのようなデジタル施策を導入すべきか。
- 農業の収益性を上げるためのIT施策を考える。
- 農業の担い手不足を解消する施策を考える。
- 農業の生産性を高めるために、自治体や企業は何をすべきか。

## 最初に置くべき前提

農業DXは対象によって答えが変わる。GDでは、最初にここを決める。

```text
農業全体だと広すぎるので、今回は日本の水田作・野菜作のような人手不足が深刻な生産現場を対象にしませんか。
ゴールは、短期的には作業時間の削減、中期的には収量・品質の安定、長期的には担い手が継続できる収益性向上に置きたいです。
```

よりPwCっぽくするなら、対象を「自治体・JA・地域の農業法人」と置く。

```text
クライアントを地方自治体またはJAと仮定し、地域農業の持続性を高める施策として考えたいです。
```

## 基礎ファクト

暗記する数字は多くなくてよい。面接・GDでは、以下だけ持っていれば十分。

- 日本の食料自給率は、令和6年度でカロリーベース38%、生産額ベース64%。
- 2024年の農地面積は427万haで、前年から2.5万ha減少。
- 2023年度に新たに発生した荒廃農地は2.5万ha、再生利用された荒廃農地は1.0万ha。
- 荒廃農地の主な理由には、農業者の高齢化、病気、死亡、担い手・労働力不足がある。
- スマート農業技術活用促進法は2024年6月成立、2024年10月施行。生産方式革新実施計画と開発供給実施計画の2つの認定制度があり、認定を受けた農業者や事業者は金融等の支援を受けられる。
- 農水省のスマート農業実証プロジェクトは、先端技術を生産現場に入れて、経営への効果を明らかにする事業。
- WAGRIは、農地、農薬、肥料、気象などの農業データを連携させ、Webアプリ開発やデータ活用をしやすくする基盤。

出典は末尾にまとめる。

## 農業DXの本質

### スマート農業と農業DXの違い

```text
スマート農業:
ロボット、ドローン、センサー、AIなどを使って、個別作業を省力化・高精度化すること。

農業DX:
生産、経営、流通、販売、行政支援までをデータでつなぎ、農業のやり方自体を変えること。
```

GDでは、スマート農業だけで終わると「機械を入れただけ」になる。  
農業DXまで持っていくには、以下まで話す。

- どの作業を減らすか。
- どのデータを取るか。
- 誰が使うか。
- 導入費用をどう下げるか。
- 農家の行動をどう変えるか。
- 収量、品質、利益、継続率にどう効くか。

## 農業の課題構造

### 1. 人手不足・高齢化

農業は、田植え、収穫、防除、草刈りなど、短い期間に作業が集中する。  
人手不足の本質は「年間を通じて人が足りない」だけでなく、「繁忙期に一気に人が必要になる」こと。

施策の方向性:

- 重い作業を機械化する。
- 見回りや記録を遠隔化する。
- 繁忙期だけ使える支援サービスを増やす。
- 未経験者でも作業できるようにする。

### 2. 技能継承の難しさ

農業には、天候、土壌、品種、生育状況を見て判断する暗黙知が多い。  
熟練者の勘に依存していると、若手や新規就農者が入りにくい。

施策の方向性:

- 作業記録、生育データ、収量データを残す。
- 優良農家の栽培方法を見える化する。
- 判断基準をアプリやAIで支援する。
- JAや自治体が地域全体でデータ共有する。

### 3. 収益性の低さ

農業DXの目的は、省力化だけでは弱い。  
導入費が高いので、最終的には「利益が増える」説明が必要。

施策の方向性:

- 収量を増やす。
- 品質を安定させる。
- 高単価で売れる作物や販路に寄せる。
- 需要予測で廃棄や安売りを減らす。
- 作業時間削減で規模拡大や高収益作物に時間を回す。

### 4. 小規模・分散農地

日本の農地は小さく分散している地域も多く、大型機械を入れても効率が出ない場合がある。  
スマート農機は大区画で効果が出やすいので、機械だけでは解けない。

施策の方向性:

- 農地集約。
- 機械の共同利用。
- 作業受託サービス。
- 地域単位でのデータ共有。
- 小型機械やドローンなど、分散農地でも使える技術。

### 5. 気候変動・災害・品質不安定

高温、豪雨、病害虫の発生などで、経験則だけでは対応しにくくなっている。  
農業DXは、環境データを取って、早めに判断する方向に効く。

施策の方向性:

- 気象データと圃場データの連携。
- 水管理の自動化。
- 病害虫発生予測。
- 収量・出荷予測。
- 保険、金融、行政支援へのデータ活用。

## 作業工程で分解する

農業DXのお題が来たら、まず工程に分ける。

```text
計画
農地・人員・作付け計画、資材調達、販売計画

栽培準備
耕起、施肥、播種、田植え

栽培管理
水管理、温度管理、病害虫確認、除草、防除、追肥

収穫
収穫、運搬、選別、乾燥、調製

出荷・販売
出荷量予測、販路選定、価格交渉、在庫管理

経営管理
作業記録、原価管理、利益管理、補助金・行政手続き
```

GDでは、全工程を解こうとしない。  
一番効く工程を選ぶ。

```text
今回は人手不足がテーマなので、作業時間が大きく、かつデジタルで削減余地がある栽培管理と収穫に絞りませんか。
```

## 施策が生まれる思考パターン

ここが一番大事。施策は暗記ではなく、課題から自然に出す。

### パターン1: 重い・危険・繰り返し作業が多い

課題:

- 防除、草刈り、収穫、運搬などが肉体的にきつい。
- 高齢者には負担が大きい。
- 繁忙期に人手が集中して必要。

思考:

```text
人がやる価値が低い反復作業なら、機械化・自動化・作業受託で置き換える。
```

施策:

- ドローン農薬散布。
- 自動運転トラクタ。
- 直進アシスト田植機。
- リモコン草刈機。
- 収穫・運搬ロボット。
- 作業受託サービス。

言い方:

```text
この課題は、判断よりも作業負荷の問題が大きいので、まずは防除や水管理のような反復作業から自動化するのが現実的です。
```

### パターン2: 見回り・確認に時間がかかる

課題:

- 水田の水位確認、ハウス内の温度確認、病害虫確認などで移動時間がかかる。
- 圃場が分散しているほど負担が大きい。

思考:

```text
人が現地に行って見ているだけなら、センサーと遠隔監視で置き換える。
```

施策:

- 水田水管理システム。
- 圃場センサー。
- ハウス環境センサー。
- ドローン・衛星画像による生育確認。
- 異常検知アラート。

言い方:

```text
見回りは農家の経験が必要に見えますが、実際には水位や温度など定量化できる部分も多いです。まずは見回りをデータ取得に置き換えるべきです。
```

### パターン3: 熟練者の勘に依存している

課題:

- 施肥、灌水、防除、収穫時期の判断が熟練者に依存している。
- 新規就農者が習熟するまで時間がかかる。
- 属人化しているため、地域全体にノウハウが広がらない。

思考:

```text
熟練者の判断を、データとルールに分解して、初心者でも再現できるようにする。
```

施策:

- 作業記録アプリ。
- 収量・食味データの蓄積。
- 優良農家の栽培データ共有。
- AIによる灌水・施肥支援。
- 病害虫発生予測。

言い方:

```text
担い手不足への対策は、人を増やすだけでなく、未経験者でも一定品質で作業できるようにすることが重要です。
```

### パターン4: 機械が高すぎて個別農家では買えない

課題:

- スマート農機は高額。
- 使用時期が限られるため、稼働率が低い。
- 小規模農家には投資回収が難しい。

思考:

```text
資産として所有するのではなく、サービスとして使える形にする。
```

施策:

- 農機シェアリング。
- JA・自治体主導の共同利用。
- ドローン防除の作業受託。
- 農業支援サービス事業者の育成。
- リース・サブスクモデル。

言い方:

```text
技術導入の最大の壁は性能ではなく、初期投資と使いこなしです。したがって、個別農家が買うモデルではなく、地域単位で使うサービス化が有効です。
```

### パターン5: 生産と販売がつながっていない

課題:

- 作った後に売るため、需要と供給がずれる。
- 出荷量が読めず、安売りや廃棄が発生する。
- 高単価で売れるタイミングに合わせにくい。

思考:

```text
生産データと需要データをつなぎ、売れる量・時期・品質に合わせて作る。
```

施策:

- 収量予測。
- 出荷予測。
- 小売・外食とのデータ連携。
- 需要予測に基づく作付け計画。
- 価格・需要データを使った販路最適化。

言い方:

```text
農業DXを生産現場だけで閉じると、省力化で終わります。収益性まで上げるには、出荷予測や需要データとつないで、売り方まで変える必要があります。
```

## 主要施策カード

### 施策1: 水田水管理システム

向いている課題:

- 水位確認の見回り負担。
- 圃場が分散している地域。
- 高齢農家の移動負担。
- 高温・低温への細かな水管理。

施策内容:

- 水位・水温をセンサーで取得。
- スマホで確認。
- 必要に応じて遠隔で給排水を制御。
- 異常時に通知する。

なぜ生まれるか:

水管理は農業の中でも頻度が高く、移動時間が大きい。  
一方で、水位・水温という数値で把握できるため、センサー化しやすい。

効果:

- 見回り時間削減。
- 高温・低温対策の精度向上。
- 経験の浅い人でも管理しやすい。

KPI:

- 水管理作業時間。
- 見回り回数。
- 水位異常の発生回数。
- 収量。
- 品質。

注意点:

- 通信環境。
- センサーや給排水装置の故障。
- 水路のごみ詰まり。
- 初期費用。

GDでの使い方:

```text
まず導入しやすい施策として、水管理の遠隔化が有効だと思います。水位確認は頻度が高く、移動時間も大きい一方で、数値化しやすいため、センサー導入の効果が出やすいです。
```

### 施策2: ドローン防除・肥料散布

向いている課題:

- 農薬散布の肉体的負担。
- 広い農地や中山間地での作業負荷。
- 防除適期が短い。
- 人手不足。

施策内容:

- ドローンで農薬・肥料を散布。
- 必要に応じて生育状況を空撮する。
- 散布履歴をデータとして残す。

なぜ生まれるか:

防除は重労働で、作業タイミングも重要。  
作業者の体力に依存しやすいので、機械化の優先度が高い。

効果:

- 作業時間削減。
- 作業者の身体負担軽減。
- 適期作業がしやすくなる。
- 作業履歴が残る。

KPI:

- 防除作業時間。
- 作業人数。
- 適期作業率。
- 防除効果。
- 農薬使用量。

注意点:

- 操縦者の育成。
- 飛行規制。
- 天候制約。
- 初期投資。
- 周辺住民・隣接圃場への配慮。

GDでの使い方:

```text
防除は作業負荷が高く、時期も限られるため、ドローン化の優先度が高いです。ただし個別農家が保有するより、地域の作業受託サービスとして導入する方が現実的です。
```

### 施策3: 自動操舵・直進アシスト・自動運転農機

向いている課題:

- トラクタや田植機の操作に熟練が必要。
- 長時間作業で疲労が大きい。
- 人手を増やせない。
- 未経験者に作業を任せにくい。

施策内容:

- GPS等を使って直進や作業経路を支援。
- トラクタや田植機の操作を半自動化。
- 熟練者でなくても一定精度で作業できるようにする。

なぜ生まれるか:

農機操作は、熟練者でないと作業精度が落ちやすい。  
直進・重複回避・作業経路はデジタル化しやすいため、未経験者活用に効く。

効果:

- 作業精度の安定。
- 疲労軽減。
- 未経験者の戦力化。
- 作業の重複やムダ削減。

KPI:

- 作業時間。
- 作業面積/日。
- オペレーター育成期間。
- 重複作業率。
- 燃料費。

注意点:

- 大区画の方が効果が出やすい。
- 小規模・不整形圃場では効果が限定的。
- 機械導入費が高い。
- 安全管理が必要。

GDでの使い方:

```text
自動操舵は単なる省人化だけでなく、未経験者でも作業品質を安定させる点に価値があります。ただし小規模農地では投資回収が難しいため、農地集約や共同利用とセットにすべきです。
```

### 施策4: 食味・収量コンバインと可変施肥

向いている課題:

- 圃場ごとの収量差が分からない。
- 施肥が経験依存。
- 品質が安定しない。
- 次年度の改善につながるデータがない。

施策内容:

- 収穫時に収量、水分、タンパク値などを取得。
- 圃場ごとの収量・品質マップを作る。
- 次年度の施肥設計に反映する。
- 可変施肥で必要な場所に必要な量を入れる。

なぜ生まれるか:

収穫は「結果」が最も見える工程。  
結果データを次年度の栽培に戻せば、勘ではなく改善サイクルを回せる。

効果:

- 収量ムラの把握。
- 品質安定。
- 施肥量の最適化。
- 熟練者の判断の見える化。

KPI:

- 単収。
- 品質指標。
- 肥料使用量。
- 圃場別のばらつき。
- 翌年の改善率。

注意点:

- データを取るだけでは意味がない。
- 次年度の施肥や作付けに反映する運用が必要。
- 解析・活用できる人材が必要。

GDでの使い方:

```text
収量データを取るだけではDXではなく、翌年の施肥計画に反映して初めて価値が出ます。データ取得、分析、作業変更までを一体で設計する必要があります。
```

### 施策5: 施設園芸の環境制御

向いている課題:

- ハウス栽培で温度、湿度、CO2、灌水管理が難しい。
- 収量や品質が人の経験に依存している。
- 出荷量を予測しにくい。

施策内容:

- 環境センサーでハウス内データを取得。
- 灌水、換気、加温、冷房、CO2施用などを制御。
- 収量・出荷量を予測する。
- 優良農家の管理方法を共有する。

なぜ生まれるか:

施設園芸は環境をコントロールできる余地が大きい。  
データと制御の組み合わせで、収量・品質・出荷予測に直結しやすい。

効果:

- 単収向上。
- 品質安定。
- 作業時間削減。
- 出荷予測。
- 優良ノウハウ共有。

KPI:

- 単収。
- 秀品率。
- 出荷予測精度。
- 10a当たり利益。
- 作業時間。

注意点:

- センサーを入れるだけでは増収しない。
- データをどう解釈するかが重要。
- 部会やJA単位での学習が効果的。

GDでの使い方:

```text
施設園芸では、単に作業を減らすより、環境データを使って収量と品質を上げる方向が有効です。特にJA単位で優良農家のデータを共有すると、地域全体の底上げにつながります。
```

### 施策6: 営農管理アプリ・作業記録

向いている課題:

- 作業履歴が紙や記憶に依存している。
- 原価や利益が見えにくい。
- 誰が何をしたか分からない。
- 若手や外部人材に引き継ぎにくい。

施策内容:

- 作業日誌をアプリ化。
- 圃場別、作物別、作業者別に記録。
- 農薬・肥料・作業時間・収量を管理。
- 経営分析や補助金・認証対応に使う。

なぜ生まれるか:

農業DXの土台はデータ。  
センサーやAI以前に、作業記録がなければ改善できない。

### ITで農業問題を解決するなら

```text
私は、地域単位の農業DXプラットフォームを提案します。
農業の課題は人手不足だけでなく、高額な機械を個別農家が導入しにくい点にあります。
そのため、JAや自治体が中心となり、作業記録、水管理、ドローン防除を共通基盤化し、必要な作業をサービスとして使える形にします。
短期的には作業時間を削減し、中期的には収量・出荷データを活用して販売計画まで改善することで、農家の収益性向上につなげます。
```

### スマート農業の課題を聞かれたら

```text
スマート農業の課題は、技術性能よりも、導入費用、データ連携、現場定着だと思います。
高額な農機を個別農家が買うのは難しく、またアプリや機械がばらばらだとデータが活用できません。
そのため、共同利用や作業受託サービスで費用負担を下げ、WAGRIのようなデータ基盤も活用しながら、地域単位で導入することが重要です。
```

### AI導入を聞かれたら

```text
AIは、完全自動化よりも、まず判断支援に使うべきだと思います。
農業では天候や生育状況の不確実性が大きいため、灌水、施肥、防除、出荷時期の判断をAIが提案し、最終判断は農家が行う形が現実的です。
作業記録や収量データを蓄積し、熟練者の判断を再現可能にすることで、新規就農者の育成にもつながります。
```
