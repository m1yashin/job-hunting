このファイルとこのフォルダ配下のMarkdownファイルは、文字化けを防ぐためUTF-8で開く。

## 目的

このフォルダには、企業横断で使う面接質問、質問Item、共通回答ユニットを置く。

企業横断で使う質問や回答ユニットを置く。企業ごとの面接対策は `01_選考対策/企業名/面接対策.md` に置く。

## 置き場所の使い分け

- `質問/` には、共通質問・業界別質問・職種別質問を置く。
- `質問/個別質問/` には、1問ごとの質問意図と関連回答ユニットを置く。
- `回答ユニット/` には、回答本体、30秒/1分/2分版、深掘りツリーを置く。
- 企業ごとの面接対策、想定質問、逆質問、直前確認は `01_選考対策/企業名/` に置く。
- 実際の面接ごとの記録と復習は `01_選考対策/企業名/ログ/` に置く。
- 質問ノートは入口として使い、長い回答本文は書きすぎない。
- 企業概要、事業内容、中計、競合比較などの事実本文は `02_企業研究/` に置く。

## 面接対策ノートのProperties

質問マップには以下を使う。

```yaml
---
type: interview_questions
category:
use_for: []
---
```

質問Itemには以下を使う。

```yaml
---
type: interview_question
question:
category:
related_answer_unit: []
---
```

回答ユニットには以下を使う。

```yaml
---
type: answer_unit
theme:
main_experience:
use_for: []
related_questions: []
related_companies: []
deep_dive_type: []
status:
priority:
---
```

## 回答ユニットstatusの固定語彙

`status` は回答ユニットだけに使う。質問マップと質問Itemは入口なので、状態管理を持たせない。

```text
下書き
改善中
実戦可
```

`priority` は回答ユニットだけに使い、`A/B/C` の3段階にする。
質問Itemは入口なので、優先度、難易度、statusを持たせない。

## 面接回答の基本構造

面接回答は以下の構造を基本にする。

```text
結論
→ 背景
→ 課題
→ 行動
→ 結果
→ 学び
→ 企業・職種への接続
```


## 作成・更新フロー

- 共通質問は `質問/00_共通質問.md` に集約する。
- 業界・職種ごとの質問は `質問/` の該当ファイルに追加する。
- 1問ごとの質問意図は `質問/個別質問/質問名.md` に置く。
- 回答本体と深掘りツリーは `回答ユニット/回答名.md` に置く。
- 企業ごとの対策は `01_選考対策/企業名/面接対策.md` に置く。
- 面接前：想定質問、逆質問、話す経験、確認したい職種理解を準備する。
- 面接直後：聞かれた質問、回答の詰まり、深掘りされた点を `01_選考対策/企業名/ログ/` に記録する。
- 面接後24時間以内：次回までに直すことをログの `next_action` に落とす。

## テンプレート

面接ログは `99_Templates/面接ログテンプレ.md` を使い、`01_選考対策/企業名/ログ/` に作る。
質問Itemは `99_Templates/面接質問Itemテンプレ.md` を使う。
回答ユニットは `99_Templates/回答ユニットテンプレ.md` を使う。

## 編集方針

- 丸暗記用ではなく、話す内容の骨子として作る。
- 一文を長くしすぎない。
- 抽象的な強みだけで終わらせず、具体的な行動を入れる。
- 研究説明は、面接官が非専門でも理解できるようにする。
- PM・上流工程志望では、調整力だけでなく、構造化・意思決定・価値理解を示す。
- 逆質問は、仕事内容・判断基準・顧客理解・成長環境を聞く形にする。
- 面接対策では、質問数を増やすより、少数の回答ユニットを深掘りに耐える形へ育てる。
