# PwC GD対策シート AI・新技術の社会実装

## まず結論

AI・新技術の社会実装は、「AIを導入する」ではなく、「どの業務に、どのリスク管理を置き、誰が責任を持ち、どう現場に定着させるか」を設計する話。

GDでの勝ち筋は、次の順番で考えること。

```text
対象業務を決める
AIに任せる範囲を決める
入力データと出力の使い道を決める
リスクを分類する
人の確認点を置く
小規模実証から本番展開へ進める
```

いきなり「生成AIで全部自動化」「AIエージェントに任せる」と言わない。  
PwCのGDでは、AIを使う発想より、AIを安全に業務へ入れる設計ができるかが差になる。

## GDで出そうなお題

- AIや新しい技術を実用化する際の技術的な問題について。
- 最新技術と既存の職業の親和性について。
- 特定の科学技術のメリット・デメリットを考察して仮想クライアントに提案する。
- 生成AIを企業に導入する際の課題と施策を考える。
- AIエージェントを業務で使うなら、どこまで任せるべきか。
- 生成AIによってホワイトカラー業務はどう変わるか。
- 行政や医療、金融でAIを活用する際のリスクと対策を考える。
- AIを活用して従業員の生産性を上げる施策を考える。
- AI導入に反対する現場をどう説得するか。
- AIのためのデータセンターや半導体投資をどう考えるか。

## 最初に置くべき前提

AI社会実装は範囲が広い。最初に業務と責任範囲を絞る。

```text
AI活用は広いので、今回は企業のバックオフィス業務と顧客対応業務に絞りませんか。
ゴールは、短期的には業務時間削減、中期的には品質の標準化、長期的には人が判断すべき業務に集中できる体制づくりに置きたいです。
```

クライアントを置くなら、PwCらしく「大企業の業務部門」「自治体」「金融機関」「製造業の品質管理部門」などがよい。

```text
クライアントを大企業の管理部門と仮定し、生成AIを文書作成・問い合わせ対応・ナレッジ検索に導入する前提で考えたいです。
```

## 基礎ファクト

暗記する事実は以下で十分。

- 内閣府はAI戦略ページで、AI法、人工知能基本計画、AI関連技術の活用の適正性確保に関する指針などを主要政策として示している。
- AI法は、AIのイノベーション促進とリスク対応を両立させる枠組みとして、2025年6月4日に公布・一部施行、2025年9月1日に全面施行された。
- 経済産業省はAI事業者ガイドラインを公表しており、2026年3月31日時点では第1.2版が最新版として掲載されている。
- デジタル庁は2025年5月27日に、行政の生成AI調達・利活用に係るガイドラインを策定した。生成AIの利活用促進とリスク管理を表裏一体で進める考え方が示されている。
- 内閣府にはAI・半導体ワーキンググループが設置され、AI活用と半導体・計算資源の政策論点が扱われている。
- AI社会実装では、正確性、個人情報、著作権、説明可能性、セキュリティ、差別・バイアス、責任分界、現場定着が主要論点になる。

出典は末尾にまとめる。

## このテーマの本質

### AI導入とAI社会実装の違い

```text
AI導入:
個別業務に生成AI、予測AI、画像認識、チャットボットなどを入れること。

AI社会実装:
AIを業務プロセス、組織ルール、データ基盤、リスク管理、教育、責任分界まで含めて定着させること。
```

GDでは、AI導入案だけだと「便利そう」で止まる。  
PwCらしくするなら、以下まで入れる。

- 対象業務。
- AIに任せる範囲。
- 人が確認する範囲。
- 使うデータ。
- リスクと対策。
- 導入ステップ。
- KPI。

## AI活用の分類

AI施策は、技術名ではなく業務用途で分類すると議論しやすい。

```text
検索・要約
社内規程、過去提案書、問い合わせ履歴、議事録を探す・要約する

作成支援
メール、報告書、提案書、FAQ、コード、テストケースを作る

判断支援
与信、需要予測、故障予測、在庫予測、リスク検知を支援する

自動化
定型問い合わせ、入力チェック、請求処理、RPA、AIエージェント

認識
画像、音声、書類、センサー情報を読み取る

最適化
シフト、配送、在庫、設備保全、広告配信を最適化する
```

GDでは、まず用途を決める。

```text
今回はリスクを抑えつつ効果が出やすい、検索・要約と作成支援から始めるのがよいと思います。
```

## 課題構造

### 1. 業務が属人化している

企業には、過去資料、規程、顧客対応履歴、熟練者の判断など、散らばった知識が多い。  
AIは、知識検索や要約に向く。

施策の方向性:

- 社内ナレッジ検索。
- RAG。
- FAQ自動生成。
- 過去提案書検索。
- 議事録要約。
- 熟練者ノウハウの見える化。

### 2. 定型作業に時間がかかる

メール、議事録、報告書、問い合わせ回答、コードのたたき台、テストケース作成などは、AI支援と相性がよい。  
ただし最終責任は人が持つ必要がある。

施策の方向性:

- 文書作成支援。
- コード生成。
- テストケース生成。
- 問い合わせ一次回答。
- 翻訳。
- RPAとAIの組み合わせ。

### 3. 出力をどこまで信用するかが難しい

生成AIはもっともらしい誤りを出すことがある。  
医療、金融、法務、顧客向け資料では特に危険。

施策の方向性:

- 根拠リンク付き回答。
- 人によるレビュー。
- テスト。
- 禁止用途設定。
- 機密情報入力制限。
- 出力ログ管理。

### 4. データが整っていない

AIはデータがなければ使えない。  
社内資料がばらばら、アクセス権限が曖昧、古い情報が混ざると、AIの品質が落ちる。

施策の方向性:

- データ棚卸し。
- 文書管理。
- 権限設計。
- メタデータ付与。
- データクレンジング。
- モデル評価用データセット。

### 5. 現場が使いこなせない

AIツールを配っても、使い方が分からなければ定着しない。  
逆に、使いすぎるとチェックが甘くなる。

施策の方向性:

- ユースケース別研修。
- プロンプトテンプレート。
- 部門別ルール。
- AI利用相談窓口。
- 成功事例共有。
- 利用ログ分析。

### 6. 責任分界が曖昧

AIが誤った出力をしたとき、誰が責任を持つのか。  
現場、システム部門、ベンダー、経営の役割を分ける必要がある。

施策の方向性:

- AI利用ポリシー。
- 承認フロー。
- モデルリスク管理。
- ベンダー管理。
- 人間の最終判断。
- インシデント対応。

## 業務工程で分解する

AI社会実装のお題が来たら、業務工程に分ける。

```text
企画
課題設定、ユースケース選定、費用対効果試算

データ準備
データ棚卸し、権限確認、クレンジング、匿名化

モデル・ツール選定
既製品、社内LLM、外部API、オンプレ、クラウド

実証
PoC、小規模利用、品質評価、リスク評価

業務組込
承認フロー、レビュー、ログ管理、既存システム連携

教育・定着
研修、テンプレート、利用ルール、成功事例共有

運用・改善
精度監視、リスク監視、コスト管理、モデル更新
```

GDでは全工程を解かない。  
多くの場合、「ユースケース選定」「リスク管理」「現場定着」に絞ると強い。

## 施策が生まれる思考パターン

### パターン1: 社内知識が探せない

課題:

- 規程、過去資料、顧客対応履歴が散在。
- 新人が調べるのに時間がかかる。
- 同じ質問が何度も発生する。

思考:

```text
知識が散らばっているなら、検索・要約・根拠提示で解く。
```

施策:

- 社内ナレッジAI。
- RAG。
- FAQ自動生成。
- 議事録・過去資料検索。
- 根拠リンク付き回答。

言い方:

```text
まずは誤りのリスクが比較的低く、効果が出やすい社内ナレッジ検索から始めるべきです。AIには回答だけでなく根拠資料も提示させ、人が確認できる設計にします。
```

### パターン2: 文書作成に時間がかかる

課題:

- 報告書、メール、議事録、提案書のたたき台に時間がかかる。
- 文書品質が担当者に依存する。
- レビューに時間がかかる。

思考:

```text
ゼロから作る時間が長いなら、AIにたたき台を作らせ、人が編集する。
```

施策:

- 議事録要約。
- 提案書たたき台。
- メール文面作成。
- レビュー観点チェック。
- 文章校正。

言い方:

```text
文書作成は、AIが最終成果物を作るのではなく、たたき台を作り、人が内容と責任を持って修正する形が現実的です。
```

### パターン3: 判断が属人化している

課題:

- 与信、需要予測、故障予測、在庫判断が経験に依存。
- 担当者によって判断がばらつく。
- 判断理由が残らない。

思考:

```text
判断のばらつきが大きいなら、AIは最終判断ではなく判断材料を揃える。
```

施策:

- リスクスコアリング。
- 需要予測。
- 故障予兆検知。
- 在庫最適化。
- 判断理由の可視化。

言い方:

```text
AIは判断を置き換えるより、判断材料を標準化する役割から始めるべきです。最終判断は人が行い、AIの根拠とログを残します。
```

### パターン4: 顧客対応が逼迫している

課題:

- 問い合わせが多い。
- オペレーターが同じ回答を繰り返す。
- 応答品質にばらつきがある。
- 夜間・休日対応が難しい。

思考:

```text
定型問い合わせはAI、例外・苦情・高リスク案件は人に振り分ける。
```

施策:

- AIチャットボット。
- FAQ検索。
- 問い合わせ分類。
- オペレーター支援。
- エスカレーション判定。

言い方:

```text
顧客対応では、AIに全て任せるのではなく、定型問い合わせを一次対応し、感情的な苦情や個別判断が必要な案件は人へつなぐ設計が重要です。
```

### パターン5: AI導入に反対がある

課題:

- 仕事を奪われる不安。
- 誤りへの不信感。
- 使い方が分からない。
- ルールが曖昧。

思考:

```text
反対は技術不信ではなく、役割変更と責任不明確さへの不安として扱う。
```

施策:

- 小規模実証。
- 成功事例共有。
- AI利用ルール。
- 人の役割再定義。
- 研修。
- 現場代表を巻き込む。

言い方:

```text
現場の反対には、AIを押し付けるのではなく、AIで減らす業務と人が価値を出す業務を明確にし、小規模実証で効果を見せるべきです。
```

## 主要施策カード

### 施策1: 社内ナレッジAI

向いている課題:

- 社内資料が探せない。
- 問い合わせが多い。
- 新人教育に時間がかかる。
- 属人化。

施策内容:

- 社内規程、FAQ、過去提案書、議事録、マニュアルを検索対象にする。
- AIが質問に回答し、根拠資料へのリンクを提示する。
- アクセス権限を反映する。
- 回答ログを分析し、FAQやマニュアルを改善する。

なぜ生まれるか:

社内には既に情報があるが、探せないために時間が失われている。  
生成AIは、情報検索・要約・自然文回答に向くため、最初のユースケースとして効果が出やすい。

効果:

- 調査時間削減。
- 問い合わせ件数削減。
- 新人立ち上がり短縮。
- ナレッジ標準化。

KPI:

- 検索時間。
- 問い合わせ削減率。
- 回答満足度。
- 根拠資料閲覧率。
- 新人教育期間。

注意点:

- 古い情報の混入。
- 権限管理。
- 機密情報。
- 根拠なし回答。
- 利用ログ管理。

GDでの使い方:

```text
AI導入は、まず社内ナレッジ検索から始めるのが現実的です。回答だけでなく根拠資料を提示させることで、現場が確認でき、リスクを抑えながら調査時間を削減できます。
```

### 施策2: 生成AIによる文書作成支援

向いている課題:

- 報告書作成。
- 議事録。
- メール。
- 提案書たたき台。
- 文書レビュー。

施策内容:

- 会議音声から議事録を作る。
- 報告書やメールのたたき台を作る。
- 提案書の構成案を作る。
- 誤字、表現、抜け漏れをチェックする。
- 最終確認は人が行う。

なぜ生まれるか:

文書作成は時間がかかる一方、初稿作成や要約はAIが得意。  
人は最終判断、文脈調整、顧客への責任に集中できる。

効果:

- 文書作成時間削減。
- 品質ばらつき低減。
- レビュー効率化。
- 本質業務への時間創出。

KPI:

- 文書作成時間。
- レビュー指摘件数。
- 議事録作成時間。
- AI利用率。
- 利用者満足度。

注意点:

- 機密情報入力。
- 数値・固有名詞誤り。
- 著作権。
- 顧客向け文書の責任。

GDでの使い方:

```text
生成AIは、文書の最終成果物を任せるのではなく、初稿作成や要約に使うべきです。顧客向け資料や数値は人が確認し、責任分界を明確にします。
```

### 施策3: AI問い合わせ一次対応

向いている課題:

- コールセンター逼迫。
- 同じ質問の繰り返し。
- 夜間・休日対応。
- 応答品質のばらつき。

施策内容:

- FAQと過去問い合わせを学習対象にする。
- AIが一次回答する。
- 高リスク・苦情・感情的案件は人にエスカレーションする。
- オペレーターには回答候補を提示する。

なぜ生まれるか:

問い合わせには定型と例外が混ざる。  
AIは定型対応と分類に使い、人は例外や感情対応に集中するのがよい。

効果:

- 応答時間短縮。
- オペレーター負荷軽減。
- 24時間対応。
- 顧客満足度向上。

KPI:

- 一次解決率。
- 平均応答時間。
- エスカレーション率。
- 顧客満足度。
- オペレーター処理件数。

注意点:

- 誤回答。
- 苦情対応。
- 個人情報。
- エスカレーション基準。

GDでの使い方:

```text
顧客対応では、AIに全件対応させるのではなく、定型問い合わせを一次対応し、苦情や個別判断が必要な案件は人に渡す設計が重要です。
```

### 施策4: AIエージェントの工程内利用

向いている課題:

- 複数ツールをまたぐ定型作業。
- 調査、転記、レポート作成。
- コード作成とテスト。
- バックオフィス処理。

施策内容:

- AIエージェントに、工程内の調査、資料作成、コード生成、テストケース作成、入力チェックを任せる。
- 工程間の判断、本番反映、顧客合意は人が行う。
- 操作ログ、承認フロー、権限制御を置く。

なぜ生まれるか:

エージェントは単発回答よりも、複数ステップ作業に向く。  
ただし工程をまたぐ判断や本番影響はリスクが高い。

効果:

- 定型作業時間削減。
- 作業漏れ削減。
- テスト・レビュー支援。
- 業務スピード向上。

KPI:

- 処理時間。
- 手戻り件数。
- テストカバレッジ。
- 承認待ち時間。
- エージェント実行成功率。

注意点:

- 権限過多。
- 誤操作。
- 本番環境への影響。
- 監査ログ。
- 人の承認点。

GDでの使い方:

```text
AIエージェントは、各工程内の調査や資料作成、テストケース作成には使えますが、要件定義から設計への移行や本番反映の判断は人が担うべきです。
```

### 施策5: AIガバナンス体制

向いている課題:

- 部門ごとに勝手にAIを使う。
- 機密情報入力。
- 著作権・個人情報リスク。
- 誤回答。
- ベンダー管理。

施策内容:

- AI利用ポリシーを作る。
- ユースケースをリスク別に分類する。
- 禁止用途、要承認用途、自由利用用途を分ける。
- ログ、監査、教育、インシデント対応を整備する。
- AI推進組織と現場部門の役割を決める。

なぜ生まれるか:

AIは便利なため、現場が先に使い始める。  
ルールがないと、機密情報漏洩や誤用が起こる。  
一方で厳しすぎると活用が進まない。

効果:

- リスク低減。
- 活用促進。
- 現場の安心感。
- ベンダー管理。
- 監査対応。

KPI:

- 承認済みユースケース数。
- AI利用率。
- インシデント件数。
- 研修受講率。
- ガイドライン遵守率。

注意点:

- ルールが複雑すぎると使われない。
- 推進と規制のバランス。
- 部門ごとのリスク差。
- 継続更新。

GDでの使い方:

```text
AI社会実装では、ツール導入と同時にガバナンスが必要です。禁止用途、要承認用途、自由利用用途を分け、現場が安全に使えるルールを作るべきです。
```

### 施策6: AI人材育成・現場定着プログラム

向いている課題:

- AIを使える人と使えない人の差。
- 現場の反発。
- プロンプトが属人化。
- 成果が広がらない。

施策内容:

- 部門別のAI研修。
- ユースケース別テンプレート。
- 成功事例共有会。
- AI相談窓口。
- 現場チャンピオン制度。

なぜ生まれるか:

AIは導入より定着が難しい。  
現場が「何に使えばよいか」「どこまで信じてよいか」を理解しないと、効果が出ない。

効果:

- 利用率向上。
- 業務改善アイデア増加。
- 現場抵抗低減。
- 安全な利用促進。

KPI:

- 研修受講率。
- 月間利用者数。
- ユースケース投稿数。
- 業務時間削減。
- 現場満足度。

注意点:

- 研修だけで終わらせない。
- 部門業務に合わせる。
- 成果測定。
- 使いすぎ防止。

GDでの使い方:

```text
AIはツールを配るだけでは定着しません。部門別に使い方を具体化し、テンプレートと成功事例を共有することで、現場が安全に使える状態を作る必要があります。
```

## 実例カード

### 実例1: AI法

2025年に公布・施行されたAI法は、AIの研究開発・活用を推進しつつ、リスク対応も進めるための枠組み。内閣府のAI戦略ページでは、AI法、人工知能基本計画、適正性確保に関する指針などが主要政策として示されている。

思考パターン:

```text
AI活用が急速に進む
→ イノベーションは止めたくない
→ ただしリスク対応も必要
→ 推進とガバナンスを両立する制度が必要
```

GDでの使い方:

```text
日本でもAI法により、AIの活用促進とリスク対応を両立させる方向が示されています。企業のAI導入も、活用とガバナンスをセットで設計する必要があります。
```

### 実例2: AI事業者ガイドライン

経済産業省はAI事業者ガイドラインを公表しており、AI開発者、提供者、利用者など関係主体に応じた取組の整理が進められている。2026年3月31日時点では第1.2版が最新版として掲載されている。

思考パターン:

```text
AIには開発者、提供者、利用者がいる
→ リスクは一主体だけでは管理できない
→ 役割ごとに責任と取組を整理する
```

GDでの使い方:

```text
AI導入では、ベンダー任せにも現場任せにもできません。開発者、提供者、利用者それぞれの責任を分ける必要があります。
```

### 実例3: 行政の生成AIガイドライン

デジタル庁は2025年5月27日、行政の生成AI調達・利活用に係るガイドラインを策定した。生成AIの利活用促進とリスク管理を表裏一体で進めることが示されている。

思考パターン:

```text
行政も生成AIを使いたい
→ 公的業務はリスクが高い
→ 調達・利用ルールが必要
→ 利活用促進とリスク管理をセットにする
```

GDでの使い方:

```text
行政の生成AI活用でも、単に禁止するのではなく、ガイドラインを設けて安全に使う方向です。企業でも同じように、ルールを作って活用を進めるべきです。
```

### 実例4: AI・半導体ワーキンググループ

内閣府にはAI・半導体ワーキンググループが設置され、AI活用に必要な計算資源、半導体、投資、産業競争力などが議論されている。AI社会実装は、ソフトウェアだけでなく、データセンター、電力、半導体などのインフラにも関わる。

思考パターン:

```text
AI利用が増える
→ 計算資源と半導体が必要
→ インフラ投資が必要
→ 電力・環境負荷・産業政策も論点になる
```

GDでの使い方:

```text
AI社会実装は、業務効率化だけでなく、計算資源やデータセンター、半導体投資まで含む産業政策のテーマでもあります。
```

## お題別の解き方

### お題1: 生成AIを企業に導入する際の課題と施策

最初の発言:

```text
生成AI導入は、業務効率化、データ管理、リスク管理、現場定着に分けて考えたいです。まずはリスクを抑えつつ効果が出やすい社内ナレッジ検索と文書作成支援から始めるのがよいと思います。
```

論点:

- どの業務に使うか。
- 機密情報をどう守るか。
- 出力の正確性をどう担保するか。
- 現場が使えるか。
- KPIをどう測るか。

施策案:

1. 社内ナレッジAI。
2. 文書作成支援。
3. AI問い合わせ一次対応。
4. AI利用ポリシー。
5. 部門別研修。

発表結論:

```text
私たちは、社内ナレッジAIと文書作成支援から導入することを提案します。いきなり顧客対応や意思決定を任せるのではなく、社内資料の検索・要約、議事録、報告書のたたき台作成から始めます。回答には根拠リンクを付け、人が確認するフローを置きます。同時に、機密情報入力や顧客向け利用のルールを定め、研修で現場定着を図ります。
```

### お題2: AIエージェントに仕事を任せる範囲

最初の発言:

```text
AIエージェントは、各工程内の定型作業には使えますが、工程をまたぐ意思決定や本番反映は人が責任を持つべきだと思います。
```

論点:

- 工程内か工程間か。
- 本番環境に影響するか。
- 顧客・法務・金融など高リスクか。
- ログと承認があるか。

施策案:

1. 調査、要約、資料たたき台作成。
2. コード生成とテストケース作成。
3. 問い合わせ分類。
4. 承認フロー付き業務自動化。
5. 本番前レビュー。

発表結論:

```text
AIエージェントに任せる範囲は、各工程内の調査、資料作成、コード生成、テストケース作成までが適切だと思います。一方で、要件定義から設計への移行、本番環境への反映、顧客との合意形成は人が判断すべきです。エージェントには権限を絞り、ログと承認フローを置くことで、安全に使える範囲を広げます。
```

### お題3: AI導入に反対する現場をどう説得するか

最初の発言:

```text
反対の背景には、仕事を奪われる不安、誤回答への不信感、使い方が分からない不安があると思います。技術の説明より、役割分担と小規模実証が重要です。
```

論点:

- 反対理由は何か。
- どの業務が楽になるか。
- 人の価値はどこに残るか。
- 失敗しても影響が小さい実証は何か。

施策案:

1. 現場ヒアリング。
2. 低リスク業務でPoC。
3. 業務時間削減を可視化。
4. 人の確認点を明確化。
5. 成功事例共有。

発表結論:

```text
現場を説得するには、AIで仕事を置き換えるのではなく、定型作業を減らし、人が判断や顧客対応に集中できることを示す必要があります。まず議事録作成や社内検索など低リスク業務で小規模実証し、削減時間と品質を可視化します。その上で、AIが作る部分と人が責任を持つ部分を明確にします。
```

## 施策評価軸

GDで施策を比較するときは、この6つを使う。

```text
効果:
業務時間、品質、顧客対応、判断精度にどれだけ効くか。

実現性:
既存データ・既存ツールでできるか。

リスク:
誤回答、個人情報、機密情報、著作権、差別・バイアスが管理できるか。

責任分界:
AI、現場、人間の最終判断、ベンダーの役割が明確か。

定着性:
現場が使えるか。教育・テンプレート・サポートがあるか。

拡張性:
他部門や他業務へ広げられるか。
```

発言例:

```text
施策を効果とリスクで比較すると、顧客向け自動回答よりも、まず社内ナレッジ検索や文書作成支援の方が導入しやすいと思います。
```

```text
AI導入では、精度だけでなく、誤った出力が出た場合に誰が確認し、どこで止めるかを設計する必要があります。
```

## ありがちな失敗

### 失敗1: AIで全部自動化と言う

悪い例:

```text
生成AIで全ての業務を自動化します。
```

改善:

```text
AIは定型作業やたたき台作成には有効ですが、顧客合意や本番判断など責任が重い部分は人が担うべきです。
```

### 失敗2: 精度だけを論点にする

悪い例:

```text
AIの精度を上げれば解決します。
```

改善:

```text
精度だけでなく、個人情報、機密情報、著作権、説明可能性、ログ管理、現場教育まで含めて設計する必要があります。
```

### 失敗3: データ準備を忘れる

悪い例:

```text
社内資料をAIに読み込ませます。
```

改善:

```text
社内資料には古い情報や権限の違う情報が混ざるため、データ棚卸し、権限設計、更新ルールが必要です。
```

### 失敗4: 現場にツールを配って終わる

悪い例:

```text
全社員にAIツールを配ります。
```

改善:

```text
部門ごとに使う業務、禁止用途、確認フローを定め、研修とテンプレートで定着させる必要があります。
```

### 失敗5: 顧客向けにいきなり使う

悪い例:

```text
顧客対応を全てAIチャットボットにします。
```

改善:

```text
定型問い合わせはAI、苦情や個別判断が必要な案件は人にエスカレーションする設計が必要です。
```

## 立ち回りフレーズ

### 冒頭で使う

```text
AI社会実装は広いので、まず対象業務を決めたいです。今回は効果が出やすくリスクも比較的管理しやすい、社内ナレッジ検索と文書作成支援に絞りませんか。
```

```text
AIに何を任せるかだけでなく、人がどこで確認するか、誤りが出た時にどう止めるかまで考えたいです。
```

### 議論がAI万能論に寄った時

```text
AIで全部自動化するのではなく、業務を分解して、AIに任せる部分と人が判断する部分を分ける必要があります。
```

### 施策を絞る時

```text
短期で効果が出やすいのは社内検索と文書作成支援、中期で効くのは問い合わせ対応、長期ではAIエージェントによる工程内自動化だと思います。
```

### PwCっぽくまとめる時

```text
単なるツール導入ではなく、業務プロセス、データ基盤、ガバナンス、現場教育まで含めて変革として設計する必要があります。
```

## 最強の提案パッケージ

迷ったらこの提案に寄せる。

### 生成AI業務変革プログラム

対象:

- 大企業の管理部門。
- 金融機関。
- 自治体。
- 製造業の品質・保守部門。
- コールセンター。

課題:

- 社内情報が探せない。
- 文書作成に時間がかかる。
- 問い合わせ対応が逼迫している。
- AI利用ルールがない。
- 現場に不安がある。

施策:

1. 業務棚卸しを行い、AI向き業務を「検索・要約」「作成支援」「判断支援」「自動化」に分類する。
2. まず社内ナレッジAIと文書作成支援から小規模実証する。
3. 回答には根拠リンクを付け、人が確認するフローを置く。
4. 機密情報、個人情報、顧客向け利用のルールを定める。
5. 部門別研修とプロンプトテンプレートを整備する。
6. 効果が出た業務から問い合わせ対応、AIエージェントへ広げる。

なぜ強いか:

- 効果が出やすい低リスク業務から始める。
- リスク管理を最初から入れている。
- 現場定着まで設計している。
- AI法・AI事業者ガイドラインの方向性と合う。
- PwCらしく、業務変革とガバナンスがセットになっている。

KPI:

- 文書作成時間。
- 社内問い合わせ削減率。
- AI利用率。
- 回答満足度。
- レビュー指摘件数。
- インシデント件数。
- 研修受講率。
- 業務時間削減額。

発表例:

```text
私たちは、生成AI業務変革プログラムを提案します。
AI導入では、いきなり顧客対応や意思決定を任せるのではなく、社内ナレッジ検索と文書作成支援から始めます。
社内規程や過去資料を検索できるAIを整備し、回答には根拠リンクを付け、人が確認できるようにします。
同時に、機密情報入力、顧客向け利用、著作権、ログ管理に関するルールを定めます。
小規模実証で削減時間と品質を確認したうえで、問い合わせ対応やAIエージェントによる工程内自動化へ拡張します。
```

## 30秒回答テンプレート

### AIを企業に導入するなら

```text
私は、社内ナレッジ検索と文書作成支援から導入すべきだと思います。
いきなり顧客対応や意思決定を任せると誤回答や責任の問題が大きいため、まずは社内資料の検索・要約、議事録、報告書のたたき台作成のように、人が確認しやすい業務から始めます。
回答には根拠リンクを付け、機密情報や顧客向け利用のルールを定めたうえで、効果が出た業務から拡張します。
```

### AIエージェントを聞かれたら

```text
AIエージェントは、各工程内の調査、資料作成、コード生成、テストケース作成には使えると思います。
一方で、要件定義から設計への移行、本番環境への反映、顧客との合意形成は人が判断すべきです。
権限を絞り、ログと承認フローを置くことで、安全に使える範囲を広げるのが現実的です。
```

### AI社会実装の課題を聞かれたら

```text
AI社会実装の課題は、技術精度だけではなく、データ整備、個人情報、機密情報、著作権、責任分界、現場定着だと思います。
そのため、ツール導入だけでなく、利用ポリシー、データ基盤、レビュー体制、研修をセットで設計する必要があります。
```
