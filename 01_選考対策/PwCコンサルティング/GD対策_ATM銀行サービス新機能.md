# PwC GD対策シート ATM・銀行サービスの新機能

## まず結論

ATM・銀行サービスの新機能は、「便利そうな機能を足す」ではなく、誰のどの不満を解くかを決めるテーマ。  
GDで強い答えは、利用者、銀行、社会リスクの3方向で考えること。

```text
利用者:
高齢者、外国人、現金利用者、急いでいる人、金融に不慣れな人

銀行:
窓口負担、ATM維持費、本人確認、顧客接点、アプリ移行

社会リスク:
特殊詐欺、マネーロンダリング、個人情報、デジタル格差
```

いきなり「AIを入れる」「相談機能をつける」と言わない。  
まずATMの役割を、現金処理、本人確認、手続補助、高齢者・現金利用者との接点として整理する。

## GDで出そうなお題

- ATMに1つ機能を追加するとしたら。
- とある銀行サービスに新機能を追加するなら、どんな機能がよいか。
- 銀行アプリの利用者数を増やすには。
- 高齢者にも使いやすい銀行サービスを考える。
- ATMを活用して金融詐欺を防ぐには。
- キャッシュレス化が進む中でATMの価値を高めるには。
- 銀行店舗の来店者数減少に対して、どのようなサービスを作るか。
- 地方銀行がデジタル化を進めるには。
- 銀行の顧客満足度を高めるデジタル施策を考える。
- 金融サービスでデジタル格差を解消するには。

## 最初に置くべき前提

ATMの新機能は、対象者を決めないとアイデア大会になる。

```text
ATM利用者は広いので、今回はデジタルに不慣れだが現金利用が多い高齢者と、急いでATMを使う一般利用者に絞りませんか。
ゴールは、利用者の手間を減らすことと、銀行側の窓口・問い合わせ負担を減らすことに置きたいです。
```

銀行サービスなら、

```text
銀行サービスは、アプリで完結できる層と、ATM・窓口が必要な層に分けて考えたいです。
今回は、デジタル移行を進めつつ、高齢者や金融に不慣れな人を取り残さない設計にしたいです。
```

クライアントを置くなら「地方銀行」「メガバンク」「コンビニATM事業者」「銀行アプリ運営部門」がよい。

## 基礎ファクト

暗記する事実は以下で十分。

- キャッシュレス比率は上昇しており、経済産業省によると2025年のキャッシュレス決済比率は58.0%。
- 一方で、現金利用者や高齢者、地方ではATM・窓口ニーズが残る。
- 金融庁はフィンテックやオープンAPIに関する情報を公表しており、銀行と外部サービスの連携は重要な論点。
- 警察庁は特殊詐欺対策を公表しており、ATMでの還付金詐欺や高齢者の被害防止は金融サービスの重要テーマ。
- 銀行サービスでは、本人確認、AML/CFT、個人情報、サイバーセキュリティ、金融包摂が重要。
- ATMの新機能は、便利さだけでなく、詐欺防止、操作支援、アプリ連携、窓口負担削減の視点で考えると強い。

出典は末尾にまとめる。

## このテーマの本質

### ATMの役割

```text
従来:
現金の出し入れ、振込、残高照会。

現在:
キャッシュレス化で頻度は下がるが、現金利用者、高齢者、地方、緊急時のインフラとして残る。

今後:
銀行アプリや本人確認、詐欺防止、手続補助、金融相談への入口として使える。
```

GDでは、ATMを「古いチャネル」として捨てるのではなく、デジタルと現金の接点として考えるとよい。

### 銀行サービスの分解

```text
日常取引:
入出金、振込、残高照会、支払い

資産管理:
家計簿、貯蓄、投資、ローン、保険

本人確認・手続:
住所変更、カード再発行、口座開設、各種申請

相談:
相続、ローン、資産形成、詐欺相談

リスク管理:
特殊詐欺、不正送金、マネロン、認知機能低下、なりすまし
```

## 課題構造

### 1. ATM操作が分かりにくい

高齢者や外国人、金融に不慣れな人にとって、ATMの画面は分かりにくい。  
操作ミスや問い合わせが発生する。

施策の方向性:

- やさしいモード。
- 多言語対応。
- 音声ガイド。
- 大きな文字。
- スマホ事前設定。
- 遠隔サポート。

### 2. 特殊詐欺リスクがある

ATMは還付金詐欺や振込詐欺の接点になる。  
特に高齢者の高額振込や通話しながらの操作は危険。

施策の方向性:

- 高額振込アラート。
- 通話中操作警告。
- AI行動検知。
- 家族通知。
- 一時停止・本人確認強化。
- 窓口・コールセンター接続。

### 3. 銀行アプリに移行できない層がいる

銀行はアプリ化したいが、高齢者やスマホが苦手な人は移行しにくい。  
ATMは、アプリ利用開始の支援チャネルにもなる。

施策の方向性:

- ATMでアプリ初期設定支援。
- QRコードで手続き引き継ぎ。
- ATMで本人確認。
- 操作チュートリアル。
- 店舗スタッフ連携。

### 4. 窓口負担が重い

住所変更、カード再発行、各種手続、簡単な相談で窓口が混む。  
ATMやアプリに移せる手続は移したい。

施策の方向性:

- ATM手続受付。
- ビデオ通話相談。
- 書類スキャン。
- 予約管理。
- 手続状況確認。

### 5. キャッシュレス化でATMの収益性が下がる

現金利用が減るとATMの稼働率が下がる。  
維持費を考えると、ATMの役割を現金以外へ広げる必要がある。

施策の方向性:

- アプリ連携。
- 本人確認拠点化。
- 地域金融相談。
- コンビニATMでの手続拡張。
- 提携サービス。

### 6. 金融サービスが複雑

投資、ローン、保険、相続、資産形成などは、顧客にとって難しい。  
銀行サービスの価値は、単なる取引から金融行動支援へ移る。

施策の方向性:

- 家計診断。
- 目的別貯蓄。
- 資産形成ガイド。
- ローンシミュレーション。
- 相談予約。
- AI金融コンシェルジュ。

## 利用者行動で分解する

ATM・銀行サービスのお題が来たら、利用者行動に分ける。

```text
認知
どのサービスがあるか知る

準備
カード、スマホ、本人確認、必要書類

操作
入出金、振込、手続、相談予約

確認
金額、相手先、手数料、リスク、控え

完了
取引完了、通知、アプリ連携

継続
次回の手続、資産管理、詐欺防止、相談
```

GDでは「追加機能」を出す前に、どの工程の不満を解くかを置く。

```text
今回はATMの現金機能ではなく、振込時の詐欺防止と、アプリへの手続引き継ぎに絞るのがよいと思います。
```

## 施策が生まれる思考パターン

### パターン1: 操作が難しい

課題:

- 画面が分かりにくい。
- 高齢者が迷う。
- 外国人が使いにくい。
- 金融用語が難しい。

思考:

```text
操作で迷うなら、利用者別にUIを変え、支援機能を置く。
```

施策:

- やさしいモード。
- 多言語対応。
- 音声ガイド。
- 事前スマホ入力。
- ビデオサポート。

言い方:

```text
ATMは全員に同じ画面を出すのではなく、高齢者や外国人向けにやさしいモードや多言語表示を用意するべきです。
```

### パターン2: 振込詐欺が起きる

課題:

- 高額振込。
- 通話しながら操作。
- 還付金名目。
- 急かされる。

思考:

```text
詐欺は操作中の異常行動と取引内容に現れるので、リスクを検知して止める。
```

施策:

- 高額振込アラート。
- 通話中操作警告。
- AIカメラ/センサーによる不審行動検知。
- 家族・銀行への確認通知。
- 一時停止。
- ビデオ通話確認。

言い方:

```text
ATMの新機能としては、利便性だけでなく特殊詐欺防止が重要です。高齢者の高額振込や通話しながらの操作を検知し、一時停止や銀行員確認につなげる仕組みが有効です。
```

### パターン3: アプリとATMが分断している

課題:

- アプリで途中まで手続きできない。
- ATMで入力が面倒。
- 本人確認が別々。
- 高齢者がアプリ移行できない。

思考:

```text
ATMとアプリを別チャネルにせず、事前入力と本人確認でつなぐ。
```

施策:

- アプリで振込内容事前入力、ATMでQR読み取り。
- ATMで本人確認してアプリ初期設定。
- ATM取引明細をアプリに自動保存。
- アプリからATM予約。

言い方:

```text
ATMと銀行アプリを分断せず、アプリで事前入力し、ATMでQRコードを読み取って本人確認・実行する形にすれば、操作時間と入力ミスを減らせます。
```

### パターン4: 窓口が混む

課題:

- 住所変更、カード再発行、残高証明、相談予約などで窓口が混む。
- 簡単な手続に行員時間が取られる。

思考:

```text
本人確認と書類受付ができれば、窓口手続の一部はATM・アプリに移せる。
```

施策:

- ATM手続受付。
- 書類スキャン。
- ビデオ通話。
- 相談予約。
- 手続進捗確認。

言い方:

```text
ATMを現金取引だけでなく、本人確認と手続受付のチャネルとして使えば、窓口負担を下げられます。
```

### パターン5: 金融行動が続かない

課題:

- 貯蓄・投資が続かない。
- 家計管理が面倒。
- 金融商品が難しい。

思考:

```text
銀行サービスを取引から行動支援へ広げる。
```

施策:

- 目的別貯蓄。
- 家計ダッシュボード。
- 少額積立提案。
- ローン返済シミュレーション。
- 資産形成相談予約。

言い方:

```text
銀行サービスの新機能では、単なる取引機能より、貯蓄や資産形成など顧客の金融行動を支援する機能が価値になります。
```

## 主要施策カード

### 施策1: ATM詐欺防止アラート

向いている課題:

- 高齢者の特殊詐欺。
- 高額振込。
- 通話しながらのATM操作。
- 還付金詐欺。

施策内容:

- 高齢者の高額振込や普段と違う取引を検知する。
- 通話しながらの操作を警告する。
- 「還付金」「急ぎ」などの注意喚起を画面表示する。
- 必要に応じて取引を一時停止し、銀行員・コールセンターにつなぐ。
- 本人の同意がある場合は家族通知も検討する。

なぜ生まれるか:

ATMは詐欺被害の最終接点になることがある。  
詐欺は、普段と違う高額振込や通話しながらの操作など、行動パターンに現れやすい。

効果:

- 特殊詐欺被害防止。
- 顧客保護。
- 銀行の信頼向上。
- 問い合わせ対応の効率化。

KPI:

- アラート件数。
- 取引一時停止件数。
- 被害未然防止件数。
- 高齢者高額振込の確認率。
- 誤検知率。

注意点:

- 誤検知で利用者体験を損なう。
- プライバシー。
- 家族通知の同意。
- カメラ利用の説明。
- 詐欺犯の回避行動。

GDでの使い方:

```text
ATMに追加する機能としては、利便性だけでなく詐欺防止が重要です。高齢者の高額振込や通話しながらの操作を検知し、一時停止や銀行員確認につなげることで、被害を未然に防げます。
```

### 施策2: やさしいATMモード

向いている課題:

- 高齢者の操作不安。
- 外国人利用者。
- 金融用語の難しさ。
- 操作ミス。

施策内容:

- 大きな文字。
- 手順を減らす。
- 音声ガイド。
- 多言語表示。
- よく使う操作を優先表示する。
- 操作途中でヘルプを呼べる。

なぜ生まれるか:

ATMは利用者に同じ画面を出しているが、利用者のデジタル習熟度は違う。  
高齢者や外国人向けに画面を変えれば、操作不安を下げられる。

効果:

- 操作ミス削減。
- 問い合わせ削減。
- 高齢者の利用継続。
- 外国人対応。

KPI:

- 操作完了率。
- 操作時間。
- ヘルプ呼び出し件数。
- 途中離脱率。
- 利用者満足度。

注意点:

- 画面が長くなりすぎる。
- 音声のプライバシー。
- 多言語の正確性。
- 詐欺誘導に悪用されない設計。

GDでの使い方:

```text
高齢者や外国人向けには、ATMのやさしいモードが有効です。大きな文字、多言語、音声ガイドで操作不安を下げ、銀行窓口への問い合わせも減らせます。
```

### 施策3: アプリ事前入力・ATM QR実行

向いている課題:

- ATMでの入力が面倒。
- 振込先入力ミス。
- ATM滞在時間。
- アプリとATMの分断。

施策内容:

- 銀行アプリで振込先や金額を事前入力する。
- ATMでQRコードを読み取る。
- ATM側で本人確認と最終確認を行う。
- 取引明細をアプリに保存する。

なぜ生まれるか:

ATMで長い情報を入力するのは時間がかかり、ミスも起きる。  
アプリで事前入力し、ATMで実行すれば、操作時間と入力ミスを減らせる。

効果:

- ATM操作時間短縮。
- 振込ミス削減。
- ATM待ち時間削減。
- アプリ利用促進。

KPI:

- QR実行利用率。
- ATM操作時間。
- 入力ミス件数。
- アプリ連携率。
- ATM待ち時間。

注意点:

- スマホ非利用者。
- QRコードのセキュリティ。
- 事前入力内容の確認。
- なりすまし。

GDでの使い方:

```text
ATMの新機能として、アプリで事前入力しATMでQR実行する仕組みが有効です。操作時間を短縮し、入力ミスを減らしながら、アプリ利用にもつなげられます。
```

### 施策4: ATMビデオ相談・手続受付

向いている課題:

- 窓口混雑。
- 地方店舗縮小。
- 簡単な手続の来店負担。
- 高齢者の相談ニーズ。

施策内容:

- ATMからビデオ通話で銀行員に相談できる。
- 住所変更、カード再発行、残高証明などの手続を受け付ける。
- 本人確認をATMで行う。
- 必要書類をスキャンする。
- 相談予約へつなげる。

なぜ生まれるか:

銀行店舗や窓口が減る中で、完全アプリ化できない層がいる。  
ATMを遠隔窓口として使えば、窓口負担と利用者不安を同時に減らせる。

効果:

- 窓口負担削減。
- 地方・高齢者対応。
- 手続時間短縮。
- 店舗縮小後の顧客接点維持。

KPI:

- ATM手続件数。
- 窓口来店削減数。
- ビデオ相談完了率。
- 手続処理時間。
- 顧客満足度。

注意点:

- 個室性・プライバシー。
- 本人確認。
- 通信品質。
- 相談時間の長期化。
- 詐欺への悪用防止。

GDでの使い方:

```text
ATMを現金取引だけでなく、遠隔窓口として使うこともできます。ビデオ相談や本人確認付き手続受付により、窓口負担を減らしながら高齢者や地方の顧客接点を維持できます。
```

### 施策5: 銀行アプリの金融行動支援

向いている課題:

- 銀行アプリが残高確認だけで終わる。
- 顧客接点が弱い。
- 貯蓄・投資が続かない。
- 若年層への価値提供。

施策内容:

- 家計ダッシュボード。
- 目的別貯蓄。
- 自動積立。
- 支出アラート。
- ローン返済シミュレーション。
- 資産形成コンテンツ。
- 相談予約。

なぜ生まれるか:

キャッシュレス化で取引データが増えても、顧客に価値が返らなければアプリ利用は続かない。  
銀行アプリは、単なる取引から金融行動支援へ広げるべき。

効果:

- アプリ利用率向上。
- 顧客満足度向上。
- 預金・投資・ローン接点増。
- 若年層の囲い込み。

KPI:

- 月間アクティブ率。
- 目的別貯蓄利用率。
- 積立設定数。
- 相談予約数。
- 金融商品申込率。

注意点:

- 過度な商品販売に見えないこと。
- 適合性。
- 金融リテラシー差。
- 個人情報。

GDでの使い方:

```text
銀行アプリの新機能では、残高確認だけでなく、目的別貯蓄や家計ダッシュボードなど、顧客の金融行動を支援する機能が有効です。
```

### 施策6: オープンAPI・外部サービス連携

向いている課題:

- 銀行サービスが閉じている。
- 家計簿アプリや会計ソフトとの連携。
- 中小企業の資金繰り。
- 顧客接点不足。

施策内容:

- 銀行APIで外部サービスと連携する。
- 家計簿、会計、EC、決済サービスとつなぐ。
- 法人向けには入出金・請求・資金繰りを可視化する。
- 利用者の同意に基づいてデータ連携する。

なぜ生まれるか:

顧客は銀行アプリだけで生活・事業管理をしているわけではない。  
外部サービスとつながることで、銀行データの価値が上がる。

効果:

- 顧客利便性向上。
- 法人業務効率化。
- 新サービス創出。
- 銀行の接点増加。

KPI:

- API連携数。
- 外部サービス経由利用者数。
- 法人利用率。
- データ連携同意率。
- 解約率。

注意点:

- セキュリティ。
- 同意管理。
- API品質。
- 外部事業者管理。
- 障害時責任。

GDでの使い方:

```text
銀行サービスの価値を高めるには、オープンAPIで家計簿や会計サービスと連携し、顧客の生活や事業の中で使われる形にすることが重要です。
```

## 実例カード

### 実例1: キャッシュレス決済比率の上昇

経済産業省によると、2025年のキャッシュレス決済比率は58.0%。キャッシュレス化が進む一方、現金利用者や高齢者、地方ではATM・窓口ニーズも残る。

思考パターン:

```text
キャッシュレス化が進む
→ ATM利用頻度は下がる
→ それでも現金・高齢者・緊急時のニーズは残る
→ ATMの役割を現金以外へ広げる
```

GDでの使い方:

```text
キャッシュレス化が進む中で、ATMは現金処理だけでなく、本人確認、詐欺防止、アプリ連携の接点として再定義する必要があります。
```

### 実例2: 特殊詐欺対策

警察庁は特殊詐欺対策を継続的に公表しており、還付金詐欺などATMを使った被害防止は重要な社会課題。金融機関でも高齢者の高額振込や不審な操作への注意喚起が重要になる。

思考パターン:

```text
詐欺被害はATM操作時に発生することがある
→ 最終接点で止める必要
→ 高額振込・通話中操作・不自然な行動を検知する
```

GDでの使い方:

```text
ATMの新機能では、利便性だけでなく特殊詐欺を止める社会的価値も大きいです。
```

### 実例3: フィンテック・オープンAPI

金融庁はフィンテックやオープンAPIに関する情報を公表している。銀行が外部サービスと連携することで、家計簿、会計、決済、資産管理などのサービスと銀行データをつなげられる。

思考パターン:

```text
銀行だけでは顧客接点が限られる
→ 外部アプリが生活・事業接点を持つ
→ APIで連携する
→ 銀行データの利用価値が上がる
```

GDでの使い方:

```text
銀行サービスの新機能は、自社アプリ内で完結させるだけでなく、APIで家計簿や会計サービスとつなぐ発想も重要です。
```

## お題別の解き方

### お題1: ATMに1つ機能を追加するなら

最初の発言:

```text
ATM利用者は広いので、今回は社会的インパクトが大きい高齢者の詐欺防止に絞りたいです。ATMは詐欺被害の最終接点になり得るため、取引を止める機能に価値があると思います。
```

施策案:

1. 高額振込アラート。
2. 通話中操作警告。
3. 取引一時停止。
4. ビデオ相談。
5. 家族通知。

発表結論:

```text
ATMに追加するなら、詐欺防止アラート機能を提案します。高齢者の高額振込や普段と異なる取引、通話しながらの操作を検知し、画面上で警告を出します。必要に応じて取引を一時停止し、銀行員やコールセンターにつなげます。利便性向上だけでなく、顧客保護と銀行の信頼向上につながる機能です。
```

### お題2: 銀行サービスに新機能を追加するなら

最初の発言:

```text
銀行サービスは、取引機能、資産管理、手続、相談に分けられると思います。今回は、若年層と既存顧客の利用頻度を上げるため、金融行動支援に絞りたいです。
```

施策案:

1. 目的別貯蓄。
2. 家計ダッシュボード。
3. 自動積立。
4. 支出アラート。
5. 相談予約。

発表結論:

```text
銀行サービスの新機能として、目的別貯蓄と家計ダッシュボードを提案します。残高確認だけでなく、旅行、教育、住宅など目的ごとに貯蓄目標を設定し、毎月の支出と積立状況を可視化します。必要に応じて相談予約や少額積立へつなげることで、銀行アプリの利用頻度と顧客満足度を高めます。
```

### お題3: 高齢者にも使いやすい銀行サービス

最初の発言:

```text
高齢者向け銀行サービスでは、使いやすさと詐欺防止を両立する必要があります。アプリだけでなく、ATMや窓口、電話も含めた設計にしたいです。
```

施策案:

1. やさしいATMモード。
2. ビデオ相談。
3. 高額振込アラート。
4. 家族見守り通知。
5. 操作サポート予約。

発表結論:

```text
高齢者向けには、やさしいATMモードと詐欺防止アラートを組み合わせます。大きな文字、音声ガイド、よく使う操作の優先表示で操作不安を下げます。一方で、高額振込や通話中操作など詐欺リスクが高い場合は警告や一時停止を行い、必要に応じて銀行員へつなげます。
```

### お題4: 銀行アプリの利用者数を増やすには

最初の発言:

```text
銀行アプリの利用者数を増やすには、単にダウンロードを促すのではなく、日常的に使う理由を作る必要があります。
```

施策案:

1. 家計ダッシュボード。
2. 目的別貯蓄。
3. ATM連携。
4. 手続進捗確認。
5. 支出アラート。

発表結論:

```text
銀行アプリの利用者数を増やすには、残高確認だけでなく、家計管理と目的別貯蓄を中心機能にするべきです。支出をカテゴリ別に可視化し、旅行や住宅など目的別に貯蓄目標を設定できるようにします。またATMでの取引明細をアプリに保存し、ATM利用者をアプリへ自然に移行させます。
```

## 施策評価軸

```text

銀行価値:

安全性:

実現性:
既存ATM・アプリ・本人確認基盤で実装できるか。

包摂性:
高齢者、外国人、スマホ非利用者を取り残さないか。

法規制:
個人情報、AML/CFT、本人確認、金融商品販売ルールに合うか。
```

発言例:

```text
ATM機能を評価するなら、便利さだけでなく、詐欺防止や高齢者の使いやすさも軸に入れるべきです。
```

```text
銀行アプリの新機能は、利用頻度を増やすだけでなく、過度な金融商品販売に見えないように注意が必要です。
```

## ありがちな失敗

### 失敗1: 誰向けか決めない

悪い例:

```text
ATMに相談機能を追加します。
```

改善:

```text
高齢者向けなのか、外国人向けなのか、急いでいる利用者向けなのかを決める必要があります。
```

### 失敗2: 便利機能だけ考える

悪い例:

```text
ATMで買い物もできるようにします。
```

改善:

```text
ATMは金融インフラなので、利用者の金融行動、詐欺防止、本人確認、窓口負担削減につながる機能の方が価値があります。
```

### 失敗3: 高齢者にアプリを強制する

悪い例:

```text
高齢者にも銀行アプリを使ってもらいます。
```

改善:

```text
高齢者にはATM、窓口、電話、家族支援も含めた設計が必要です。アプリ移行を支援しつつ、代替手段を残すべきです。
```

### 失敗4: 詐欺リスクを忘れる

悪い例:

```text
振込をもっと簡単にします。
```

改善:

```text
振込を簡単にするほど詐欺や誤送金のリスクもあるため、高額振込や不審な操作には確認フローを置く必要があります。
```

### 失敗5: データ連携を軽く扱う

悪い例:

```text
銀行データを外部アプリと連携します。
```

改善:

```text
外部連携には本人同意、APIセキュリティ、障害時責任、利用目的の明確化が必要です。
```

## 最強の提案パッケージ

### 安心・連携型ATM

対象:

- 高齢者。
- 現金利用者。
- スマホに不慣れな人。
- 地方の銀行利用者。
- 銀行側の窓口負担。

課題:

- 操作が難しい。
- 特殊詐欺リスク。
- ATMとアプリが分断。
- 窓口が混む。
- キャッシュレス化でATMの役割が縮小。

施策:

1. やさしいATMモードを提供する。
2. 高齢者の高額振込や通話中操作に詐欺防止アラートを出す。
3. 必要時には取引を一時停止し、銀行員・コールセンターへつなぐ。
4. アプリで振込内容を事前入力し、ATMでQR実行する。
5. ATMからビデオ相談・手続受付を行う。
6. 取引明細や手続状況をアプリへ連携する。

なぜ強いか:

- 利便性と安全性を両立している。
- 高齢者を取り残さない。
- 銀行窓口負担を減らせる。
- ATMの役割を現金以外へ拡張できる。
- PwCらしく、顧客体験と業務効率化とリスク管理がセットになっている。

KPI:

- ATM操作時間。
- 詐欺未然防止件数。
- 高額振込確認率。
- 窓口来店削減数。
- アプリ連携率。
- ビデオ相談完了率。
- 利用者満足度。
- 誤検知率。

発表例:

```text
私たちは、安心・連携型ATMを提案します。
キャッシュレス化が進む一方で、高齢者や現金利用者にとってATMは重要な金融接点です。
そこで、大きな文字や音声ガイドのやさしいATMモードを導入し、操作不安を下げます。
同時に、高齢者の高額振込や通話しながらの操作には詐欺防止アラートを出し、必要に応じて取引を一時停止して銀行員につなげます。
さらに、銀行アプリで振込内容を事前入力し、ATMでQR実行することで、操作時間と入力ミスを減らします。
```

### 金融行動支援アプリ

対象:

- 若年層。
- 子育て世代。
- 資産形成初心者。
- 既存銀行アプリ利用者。

課題:

- 銀行アプリの利用頻度が低い。
- 残高確認だけで終わる。
- 貯蓄・投資が続かない。
- 顧客接点が弱い。

施策:

1. 家計ダッシュボードを提供する。
2. 目的別貯蓄を設定できるようにする。
3. 自動積立・支出アラートを出す。
4. ローンや資産形成のシミュレーションを提供する。
5. 必要時に相談予約へつなげる。
6. ATM取引や外部家計簿サービスと連携する。

KPI:

- 月間アクティブ率。
- 目的別貯蓄設定数。
- 自動積立設定数。
- 相談予約数。
- アプリ継続率。
- 金融商品申込率。

発表例:

```text
銀行サービスの新機能として、金融行動支援アプリを提案します。
銀行アプリを残高確認だけで終わらせず、家計ダッシュボード、目的別貯蓄、自動積立、支出アラートを提供します。
これにより、利用者は日常的にアプリを使う理由が生まれ、銀行側も資産形成やローン相談への接点を作れます。
ただし過度な商品販売に見えないよう、利用者の目的達成を中心に設計します。
```
