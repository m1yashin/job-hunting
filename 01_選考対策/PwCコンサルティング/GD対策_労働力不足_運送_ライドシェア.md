# PwC GD対策シート 労働力不足・運送業界・ライドシェア

## まず結論

運送業界・労働力不足・ライドシェアは、「人が足りないからマッチングアプリを作る」では浅い。  
GDで強い答えは、需要を減らす、需要を平準化する、稼働率を上げる、供給を増やす、業務を自動化する、の5方向で整理すること。

```text
需要を減らす
  再配達削減、まとめ配送、受け取り場所変更

需要を平準化する
  配送予約、時間帯分散、荷主との納期調整

稼働率を上げる
  共同配送、帰り荷マッチング、積載率向上、ルート最適化

供給を増やす
  日本版ライドシェア、スポット人材、副業ドライバー、作業分担

業務を自動化する
  配車最適化、倉庫自動化、配送ロボット、自動運転
```

いきなりライドシェアを全面解禁する話にしない。  
日本では安全、事故時責任、運転手管理、既存タクシー業界、地域差の論点が大きい。  
短期では「不足する時間・地域に限定し、管理主体を明確にした供給補完」として話すと強い。

## GDで出そうなお題

- 日本の労働力不足に対応するには。
- 運送会社の事業継続・運送リソース確保に向けた施策と実現課題を考える。
- 運送業界が抱える課題と解決策を考える。
- 運送業界のリソース不足を解消するための施策を提案する。
- これまでタクシー業界に関与していなかった会社がライドシェアに参入する際の課題を考える。
- 公共交通機関の利用促進を図る施策を考える。
- 地方の移動課題を解決するデジタル施策を考える。
- 人手不足対策としてライドシェアを導入すべきか。
- 物流2024年問題に対して企業は何をすべきか。
- EC拡大による配送負担をどう解決するか。

## 最初に置くべき前提

運送とライドシェアは、同じ「移動・輸送」でも対象が違う。

```text
労働力不足は広いので、今回は物流のトラック輸送と、地域移動のタクシー不足に絞りませんか。
物流では再配達や積載率、ライドシェアでは不足する時間・地域への供給補完を中心に考えたいです。
```

クライアントを置くなら、

```text
物流なら、EC事業者・小売・物流会社。
ライドシェアなら、地方自治体・タクシー会社・新規参入企業。
```

PwCらしく言うなら、

```text
単なるアプリ導入ではなく、荷主、物流会社、消費者、ドライバーの行動変容まで含めて設計したいです。
```

## 基礎ファクト

暗記する事実は以下で十分。

- 物流の2024年問題では、トラックドライバーの時間外労働に上限規制が適用され、輸送力不足が懸念された。
- 国土交通省などの資料では、対策を講じない場合、2024年度には輸送能力が14.2%、2030年度には34.1%不足する可能性が示されている。
- 物流革新では、荷主・物流事業者・消費者が協力し、荷待ち・荷役時間削減、積載率向上、共同配送、再配達削減、標準的運賃、物流DXなどが重要視されている。
- 日本版ライドシェアは、タクシー事業者の管理の下で、地域交通の不足する地域・時期・時間帯に、自家用車や一般ドライバーを活用する枠組みとして始まった。
- 国土交通省は、日本版ライドシェアについて、アプリデータ等に基づき、タクシーが不足する地域・時期・時間帯を特定する考え方を示している。
- 物流・交通のDXでは、需要予測、配車最適化、マッチング、共同利用、データ連携、安全管理が重要。

出典は末尾にまとめる。

## このテーマの本質

### 物流DXとライドシェアの違い

```text
物流DX:
モノの移動を、データ・自動化・共同配送・需要調整で効率化すること。

ライドシェア:
人の移動に対して、既存交通が不足する地域・時間に、一般ドライバーや自家用車も活用して供給を補完すること。

共通点:
需要と供給の偏りを、データと運用設計で埋めること。
```

GDでは、物流とライドシェアを同じ「マッチング」で語ると危ない。  
物流は荷主・消費者の行動変容が重要。  
ライドシェアは安全・管理・責任分界が重要。

## 課題構造

### 1. ドライバー不足

物流でもタクシーでも、ドライバー不足は構造的な問題。  
高齢化、長時間労働、賃金、拘束時間、夜間・休日勤務、地方の人口減少が絡む。

施策の方向性:

- ドライバーの拘束時間削減。
- 荷待ち・荷役時間削減。
- シフト・配車最適化。
- 副業・スポット人材活用。
- 日本版ライドシェア。
- 自動運転・配送ロボット。

### 2. 需要が偏っている

物流では、セール時期、時間指定、再配達、当日配送などで需要が集中する。  
タクシーでは、雨天、終電後、観光地、イベント時、地方の朝夕などに需要が集中する。

施策の方向性:

- 需要予測。
- 動的価格・インセンティブ。
- 予約・事前配車。
- 時間帯分散。
- 共同配送。
- ピーク時限定供給。

### 3. 稼働率・積載率が低い

物流では、片道は荷物があるが帰りは空、同じ地域へ複数社が別々に配送、トラックの積載率が低いなどの非効率がある。  
タクシーでは、空車回送や待機時間がある。

施策の方向性:

- 帰り荷マッチング。
- 共同配送。
- 積載率可視化。
- 配送ルート最適化。
- 共同拠点。
- 空車位置データ活用。

### 4. 消費者の便利さが物流負担を増やしている

送料無料、即日配送、細かい時間指定、再配達は便利だが、運送負担を増やす。  
消費者体験を壊さずに、配送負担を下げる設計が必要。

施策の方向性:

- まとめ配送割引。
- 置き配。
- 宅配ロッカー。
- 店舗受取。
- 再配達有料化またはポイント設計。
- 配送日時の事前確定。

### 5. 安全・責任・規制が重い

ライドシェアは、単にマッチングすればよいわけではない。  
事故時責任、保険、ドライバー審査、車両管理、運行管理、苦情対応、運賃、既存タクシーとの関係がある。

施策の方向性:

- タクシー事業者管理。
- ドライバー審査。
- 運行ログ。
- 保険加入。
- 評価・通報。
- 地域・時間限定。
- 自治体・交通事業者との連携。

## 工程で分解する

物流のお題なら、工程はこう分ける。

```text
受注
需要予測、注文、配送日時指定

倉庫
ピッキング、梱包、在庫、出荷

幹線輸送
拠点間輸送、積載率、帰り荷、共同配送

ラストワンマイル
宅配、置き配、再配達、配送ルート

受け取り
自宅、ロッカー、店舗、職場

経営管理
ドライバー勤務、車両稼働、運賃、燃料、人件費
```

ライドシェアなら、工程はこう分ける。

```text
需要発生
雨、終電後、観光、通院、通学、イベント

供給確認
タクシー台数、空車位置、一般ドライバー登録

配車
マッチング、到着予測、料金表示

乗車
本人確認、安全確認、運行ログ

降車
決済、評価、苦情対応

管理
保険、事故対応、運転者教育、地域・時間制限
```

GDでは全工程を解かない。

```text
物流なら、再配達と積載率に絞る。
ライドシェアなら、タクシー不足が顕在化する地域・時間帯に絞る。
```

## 施策が生まれる思考パターン

### パターン1: 人が足りない

課題:

- ドライバー不足。
- 長時間労働。
- 地方や夜間で人が集まらない。
- 高齢化。

思考:

```text
人が足りないなら、採用だけでなく、1人あたりの無駄時間を減らす。
```

施策:

- 荷待ち・荷役時間削減。
- 配車最適化。
- シフト最適化。
- 共同配送。
- 介在業務の自動化。
- ライドシェアによるピーク補完。

言い方:

```text
ドライバー不足は採用だけでは解けないので、荷待ちや空車回送など、ドライバーが価値を生んでいない時間を減らすべきです。
```

### パターン2: 需要がピークに偏る

課題:

- セール時期や時間指定で配送が集中する。
- 雨天や終電後にタクシー需要が集中する。
- 需要ピークだけ供給が足りない。

思考:

```text
ピークが問題なら、需要を平準化するか、ピーク時だけ供給を増やす。
```

施策:

- 配送予約。
- 時間帯別料金・ポイント。
- まとめ配送。
- ピーク予測。
- ピーク時限定ライドシェア。
- イベント時の臨時供給。

言い方:

```text
供給を常に増やすと非効率なので、需要が集中する時間帯を予測し、そこだけ供給を増やす、または需要を分散させる設計が必要です。
```

### パターン3: トラックが空で走っている

課題:

- 帰り荷がない。
- 積載率が低い。
- 複数社が同じ地域に別々に配送。

思考:

```text
車両が走っているのに荷物が少ないなら、積載率と共同利用を上げる。
```

施策:

- 帰り荷マッチング。
- 共同配送。
- 共同拠点。
- 荷主間データ連携。
- 積載率ダッシュボード。

言い方:

```text
輸送力不足に対しては、車両数を増やすだけでなく、既存車両の積載率を上げることが重要です。帰り荷マッチングや共同配送で空車・低積載を減らせます。
```

### パターン4: 再配達が多い

課題:

- 受取人不在。
- 配送日時が合わない。
- 再配達でドライバー時間が増える。

思考:

```text
配送失敗が多いなら、受け取り方法を増やし、確実に一回で届ける。
```

施策:

- 置き配。
- 宅配ロッカー。
- 店舗受取。
- コンビニ受取。
- 配送日時リマインド。
- 再配達ポイント設計。

言い方:

```text
ラストワンマイルでは、配送効率よりも受け取り失敗を減らすことが重要です。置き配やロッカー、店舗受取を標準化することで、再配達を減らせます。
```

### パターン5: 新規参入企業がライドシェアをやりたい

課題:

- タクシー業界の知見がない。
- 安全管理が難しい。
- 事故時責任が曖昧。
- 規制・自治体調整が必要。

思考:

```text
移動サービスはアプリだけではなく、運行管理と安全責任が中心。
```

施策:

- タクシー会社と提携。
- 地域・時間限定で開始。
- ドライバー審査・教育。
- 保険・事故対応体制。
- 乗客評価・通報機能。
- 需要データに基づく供給設計。

言い方:

```text
ライドシェア参入では、マッチングアプリよりも、誰が運行管理と安全責任を負うかが重要です。まずはタクシー会社や自治体と連携し、タクシー不足が明確な時間・地域に限定して始めるべきです。
```

## 主要施策カード

### 施策1: 配送需要予測・配車最適化

向いている課題:

- 配送需要の偏り。
- ドライバー不足。
- ルートの非効率。
- 突発的な配送増。

施策内容:

- EC注文、天気、曜日、イベント、セール情報から配送需要を予測する。
- ドライバー、車両、配送先、時間指定をもとに配車を最適化する。
- リアルタイムでルートを組み替える。
- ドライバーアプリで配送順や注意事項を提示する。

なぜ生まれるか:

配送需要はランダムではなく、曜日、天気、セール、地域で偏る。  
需要を予測できれば、前もって人員・車両・拠点を配置できる。

効果:

- 走行距離削減。
- 配送件数/人の増加。
- 残業削減。
- 配達遅延削減。
- 燃料費削減。

KPI:

- 1人あたり配送件数。
- 走行距離。
- 積載率。
- 配達遅延率。
- 残業時間。
- 燃料費。

注意点:

- データ精度。
- 現場の例外対応。
- ドライバーへの過負荷。
- 既存システム連携。

GDでの使い方:

```text
物流リソース不足には、まず配送需要予測と配車最適化が有効です。需要が集中する地域・時間を予測し、車両と人員を事前配置することで、同じ人数でも処理能力を上げられます。
```

### 施策2: 共同配送・共同拠点

向いている課題:

- 積載率低下。
- 複数社の重複配送。
- 地方・過疎地の配送効率低下。
- 物流拠点の分散。

施策内容:

- 複数企業の荷物を共同拠点でまとめる。
- 同じ地域への配送を共同化する。
- 地方では自治体・小売・物流会社が連携する。
- 配送データを共有し、積載率を高める。

なぜ生まれるか:

各社が個別最適で配送すると、同じ地域に低積載の車両が何台も走る。  
地域単位・業界単位で共同化すれば、少ないドライバーで配送できる。

効果:

- 積載率向上。
- 走行距離削減。
- ドライバー負担軽減。
- CO2削減。
- 地方配送網の維持。

KPI:

- 積載率。
- 共同配送参加企業数。
- 走行距離。
- 車両台数。
- 配送コスト。
- CO2排出量。

注意点:

- 競合企業間のデータ共有。
- 荷物の品質・責任分界。
- 配送遅延時の責任。
- 標準化。

GDでの使い方:

```text
運送リソース不足には、各社が個別にドライバーを増やすより、共同配送で積載率を上げる施策が有効です。特に地方や過疎地では、企業横断で配送網を維持する必要があります。
```

### 施策3: 再配達削減パッケージ

向いている課題:

- ラストワンマイルの負担。
- 受取人不在。
- ドライバーの二度手間。
- EC配送増。

施策内容:

- 置き配を標準選択肢にする。
- 宅配ロッカー・コンビニ受取を拡充する。
- 配送予定通知と受け取り変更を簡単にする。
- まとめ配送にポイントを付ける。
- 再配達を減らすインセンティブを設計する。

なぜ生まれるか:

配送そのものを効率化しても、不在で再配達が発生すれば効果が薄い。  
一回で受け取れる設計にすると、ドライバー時間を直接削減できる。

効果:

- 再配達率低下。
- ドライバー拘束時間削減。
- 顧客満足度向上。
- CO2削減。
- 配送コスト削減。

KPI:

- 再配達率。
- 置き配利用率。
- ロッカー受取率。
- 配達完了率。
- 顧客満足度。
- 配送コスト/件。

注意点:

- 盗難リスク。
- 冷蔵・冷凍品。
- 高齢者や集合住宅の事情。
- 再配達有料化は反発があり得る。

GDでの使い方:

```text
物流2024年問題への短期施策として、再配達削減は効果が出やすいです。置き配、ロッカー、コンビニ受取、配送通知を組み合わせ、受け取り失敗を減らすべきです。
```

### 施策4: 荷主・物流会社の予約制バース管理

向いている課題:

- 荷待ち時間。
- 荷役時間。
- 倉庫・工場での待機。
- ドライバー拘束時間。

施策内容:

- トラックが到着する時間を予約制にする。
- バースの空き状況を可視化する。
- 荷主側の荷役準備状況を共有する。
- 到着遅延や混雑をリアルタイムで調整する。

なぜ生まれるか:

ドライバー不足の中で、運転していない待機時間は大きなムダ。  
荷主側の業務も含めて変えないと、物流会社だけでは解決できない。

効果:

- 荷待ち時間削減。
- ドライバー拘束時間削減。
- 倉庫作業の平準化。
- 配送遅延削減。
- 労働環境改善。

KPI:

- 平均荷待ち時間。
- バース利用率。
- ドライバー拘束時間。
- 到着遅延率。
- 荷役完了時間。

注意点:

- 荷主の協力。
- 倉庫側の運用変更。
- 予約変更時の調整。
- 中小事業者のIT導入。

GDでの使い方:

```text
運送業界の人手不足は、物流会社だけでなく荷主側の問題でもあります。荷待ち時間を減らすため、予約制バース管理を導入し、ドライバーの拘束時間を削減するべきです。
```

### 施策5: 帰り荷マッチング

向いている課題:

- 空車回送。
- 片荷輸送。
- 積載率低下。
- 中小運送会社の非効率。

施策内容:

- 目的地から戻るトラックと、帰り方面の荷物をマッチングする。
- 荷主、物流会社、運送会社の空き車両・荷物情報を連携する。
- 条件に合う荷物を推薦する。

なぜ生まれるか:

トラックが空で走るのは、輸送力不足の中で大きなムダ。  
新しいドライバーを増やさなくても、既存輸送力の使い方を改善できる。

効果:

- 積載率向上。
- 収益性向上。
- 走行距離あたり売上向上。
- CO2削減。

KPI:

- 帰り荷成約率。
- 空車走行率。
- 積載率。

```text
短期的には、置き配、ロッカー、配送通知で再配達を減らし、中期的には複数社の荷物を共同拠点に集約して配車最適化を行います。
これにより、ドライバーを増やすだけでなく、既存の輸送能力を最大化できます。
```

### ライドシェアを聞かれたら

```text
ライドシェアは、全面解禁ではなく、タクシー不足が明確な地域・時間帯に限定して導入すべきです。
利便性は高い一方で、安全管理、事故時責任、保険、ドライバー品質の論点が大きいため、タクシー会社や自治体の管理下で始めるのが現実的です。
特に地方の通院・買い物や観光地のピーク需要を補完する用途に向いています。
```

### 労働力不足を聞かれたら

```text
労働力不足への対応は、人を増やす、業務を減らす、稼働率を上げる、需要を平準化する、の4方向で考えるべきです。
運送業界であれば、採用だけでなく、再配達削減、荷待ち時間削減、共同配送、配車最適化を進めることで、同じ人数でも処理できる量を増やせます。
```
